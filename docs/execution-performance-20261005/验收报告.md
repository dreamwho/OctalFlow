# 执行性能优化验收（2026-10-05）

本轮完成最先影响结果可见性和等待时间的三项优化：Worker 查询与落盘并行、Omni 状态等待与完成通知、工作台日志 SSE 与重复请求合并。保留既有任务身份、单 Omni Worker、租约、管理员配置与资源额度。服务器尚未更新。

## 真实 Omni 样本

真实 Google AI Studio、`gemini-omni-1.1-flash`、三张参考图、1080p、9:16、10 秒。Provider 任务 `vt_29e87008cebf51dc`，App 任务 `409e1b0a-41d9-41c6-b90b-bf66a01bd450`。没有通过自动重提掩盖失败。

阶段日志以秒为精度，阶段相加与任务浮点耗时可能存在舍入差。浏览器启动至生成状态确认从约 73 秒降至约 18 秒。总耗时减少约 33.3 秒（约 21.7%），但这只是同规格单次样本；提示词、Google 排队与网络均可能影响上游耗时，不能当作平均值、P95 或并发吞吐提升。

Provider 完成后约 **40 毫秒**，App 重新查询原任务；约 **213 毫秒**后原任务进入 `success/completed` 并完成媒体落盘。此时未打开 Canvas，也未通过浏览器 GET 推动任务完成。完成通知返回 HTTP 200，随后打开 Canvas 验证终态与原任务一致。

成片是 H.264 1080×1920 视频、10.000 秒，含 AAC 音轨、容器时长 10.005 秒，共 1,561,462 字节。App 媒体接口返回 HTTP 200，文件与 Provider 原片逐字节一致，SHA-256：`feaf5cd75ad6aae07c513c657b5721feb7b2cdef791be0e70357ee04b4320b4c`。Canvas 在 1440px 实际播放时间前进；390px、430px 刷新后仍恢复原视频，媒体固有尺寸有效，没有横向页面溢出。

真实测试首先发现旧模型按钮选择器只匹配 Gemini，而当前 Studio 默认模型为 Gemma；该尝试 `vt_87787747ec8354d3` 已持久化失败，回调成功送达，没有把它当作出片成功。修复后使用实际 `ms-model-selector` 控件，并等待预热请求结束再切换模型；浏览器夹具同时覆盖 Gemma 与 Gemini 初始模型。最终成功任务是明确修正后的一次新测试。

## 执行与状态同步

- Worker 在原有 20 个任务总预算内为已准备好的结果预留最多 4 个落盘槽；查询和落盘同时开始，慢 Provider 查询不再阻塞本批已有结果落盘。使用可控阻塞查询测试确认落盘先完成；未增加总并发或 Provider 账号并发。
- Omni 使用 DOM 的会话、运行按钮、模型参数、Download 与配额状态等待，删除正常路径固定睡眠与十秒 Download 轮询。既有执行超时保持原语义，未增加拍脑袋的重试、延时或限制。
- Omni 完成通知只能发送到管理员配置的内部 App 地址；使用独立 Provider 密钥，凭已保存的上游 ID 唤醒任务。App 重新查询真实 Provider，再按既有阶段落盘。通知不接收结果 URL、不创建任务、不清除活动租约、不复活终态；通知与慢查询交错时保留唤醒状态。失败通知仍保留原有 Worker 查询兜底。
- PostgreSQL 日志触发器只在事务提交后发布所属用户 ID；回滚不发布。SSE 不发送提示词和媒体，只通知登录用户重新按用户、工作台、分页读取。文件 Provider 在持久化后发出同进程通知。
- 工作台合并同类型正在执行的刷新请求，最多保留一次后续刷新；后台更新不反复显示初始加载态。SSE 正常连接时停止原三秒整页列表轮询；既有十五秒 SSE 心跳仅补偿生成中记录；断开使用原轮询，隐藏页面关闭连接并暂停请求。
