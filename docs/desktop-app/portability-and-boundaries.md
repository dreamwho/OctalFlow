# 三版本渠道可移植性与数据边界基线

核查日期：2026-09-22。依据当前 `web/src/lib/channel-protocol-registry.ts`、`apps/desktop/scripts/prepare-runtime.mjs`、`apps/desktop/src/main/runtime-controller.mjs`、`web/src/proxy.ts` 和当前测试结果。这里的“可移植”只说明实现路径与待验证事项；没有实测的平台一律不标为通过。

## 渠道清单与平台门槛

| 协议 ID | 当前实现类别 | macOS arm64 证据 | macOS x64 / Windows x64 门槛 |
| --- | --- | --- | --- |
| `geminiai` | Provider 管理，Camoufox 与独立浏览器启动器 | Sidecar 预检及本机启动烟测；没有本轮真实模型生成验收 | 各自冻结服务、浏览器及原生依赖，验证登录、代理、生成与结果回收 |
| `dola` | Provider 管理，Camoufox/协议生成 | Sidecar 预检及空账号健康检查；没有本轮真实模型生成验收 | 各自冻结服务、浏览器及原生依赖，逐模型/比例/时长验收成片 |
| `chatgpt-api` | 独立 Provider 服务 | Sidecar 已纳入预检及管理员版打包启动 | 各自冻结服务，核对许可证、账号目录、模型生成与日志 |
| `gemini-tools` | Node OAuth / Cloud Code 服务 | Web 代码存在；桌面 OAuth、重启与结果未验收 | 验证系统浏览器回调、Token 安全存储、平台网络和模型结果 |
| `dreamina-cli` | 本地 CLI | arm64 可执行文件纳入预检；未完成实际生成矩阵 | 各自冻结 CLI，验证授权、图片/视频、代理、输出与错误恢复 |
| `openai`, `gemini`, `yumeng`, `seedance`, `stable-diffusion`, `volcengine-video` | 服务端 HTTP 协议适配 | Web 路由与协议配置存在；桌面管理员版尚未逐渠道生成 | 核实供应商桌面直连条款、回调/固定 IP、代理与媒体访问；逐渠道实际生成 |
| `sub2api`, `newapi`, `lingkeai`, `minimax-h3`, `minimax-h3-official` | 服务端 HTTP 协议适配 | 同上 | 同上；视频异步任务还需重启后状态/结果回收 |
| `minimax-audio`, `aliyun-bailian-audio`, `tencent-tokenhub-music` | 服务端 HTTP 音频适配 | 同上 | 同上；额外验证音频二进制、对象存储和下载路径 |
| `custom`, `compatible`, `auto` | 用户自定义/兼容协议 | 协议配置入口存在；无法把任意 Base URL 视为已验收 | 按用户实际端点逐项确认鉴权、CORS/回调、任务状态与媒体来源 |

注册表中 `dreamyo-recommended`、`seedance-special`、`globalaiopc` 已从当前协议选择列表退休，但旧定义仍保留用于既有配置解析；不把它们算作新的打包通过渠道。魔法代理、通用代理、链式代理是渠道出口能力，不是模型协议；桌面包对 Mihomo、FFmpeg/FFprobe 和视频深度推理有目标架构文件预检，但三种代理模式尚未完成双平台端到端请求矩阵。

目前 `prepare-runtime.mjs` 对所有版型要求同一组 Sidecar、浏览器和媒体工具，并复制完整 Next standalone。该预检只能证明文件存在；不能证明不同 CPU/系统上的动态库、浏览器指纹、代理链、OAuth、供应商条款、固定 IP 或视频回调可用。正式跨平台门禁按每个渠道执行“配置 → 提交 → 状态轮询/回调 → 实际媒体 → 日志 → 重启恢复”，且必须记录目标 OS/架构与签名状态。

## 数据归属与 API 契约

| 数据或操作 | Web | 商用桌面 | 管理员本地 |
| --- | --- | --- | --- |
| 身份、积分、支付、商品、订单 | 云端 PostgreSQL，服务端实时鉴权与记账 | 云端权威；本机仅保存加密设备刷新凭据和云端 ID 到本地 ID 的映射 | 不存在云端账号/积分/订单 |
| Canvas、素材、生成日志 | 当前 Web 服务端库及媒体存储 | 本地为主；用户主动购买和启用后才上传云端 OSS | 本地独立数据目录 |
| 魔法/通用/链式代理与五类本地 Provider 配置 | 云端后台配置 | 当前登录用户本机配置；未来可加密漫游，不能读取云端管理员密钥 | 本机配置，独立于商用版 |
| 模型生成 | 云端执行并按原规则扣积分 | 每条绑定固定 `local` 或 `cloud`；本地不扣平台积分，云端实时提交并扣费 | 全部本地执行；第三方供应商可能另收费 |
| 云存储与作品、公告、公共 Skill/提示词 | 云端 | 云端 API，非实时只读数据可按版本/ETag 缓存 | 不接入 |

当前实现与目标的差距：商用桌面 `web/src/proxy.ts` 暂时对未接通的生成路径返回 503；本地用户映射并不等于云端支付授权。云存储已具备额度账户、原始字节上传与归属下载基础，但桌面同步客户端、套餐、删除释放和真实 OSS/PG 联调未完成。管理员本地包仍复制完整 Web Runtime，并未在构建时裁掉云业务代码；代理层的 403 不是构建级隔离。

任务创建契约必须在入口固定 `executionLocation`、`channelId`、`modelId`、本地/云端用户 ID、幂等请求 ID、版本与费用归属；任务查询和恢复只能按原归属路由。禁止本地失败后自动改走云端扣费，禁止把本地 Session 或本地余额提交到云端作支付依据。云端积分只由云端事务扣减/退款，本地 Provider 请求日志和云端计费记录须通过稳定请求 ID 对齐。

## 安全与复测基线

| 威胁 / 失效模式 | 当前措施 | 尚需证据 |
| --- | --- | --- |
| 修改前端 URL、请求头绕过版本或账务 | 包内版型、loopback Runtime 令牌、商用生成 503、云端设备令牌校验 | 云端混合路由接通后的越权和零积分绕过测试 |
| 安装包泄漏 Cookie、API Key、管理员密钥 | 打包白名单、standalone 跟踪排除并清理 `.data`、运行数据独立目录；桌面 Runtime/设备刷新凭据使用系统安全存储 | 对每个目标安装包做文件/字符串扫描与干净机验证；本地 Provider 密钥仍需逐类加密引用 |
| 旧明文 Runtime 文件与密钥丢失 | 首次启动原子迁移到密文，失败不替换旧密钥 | macOS x64、Windows x64 的 Keychain/DPAPI 迁移与恢复 |
| 同步串号、跨用户读文件、超额上传 | 云端对象按用户路径及数据库归属查询；上传前预留并校验实际摘要 | 真实 PG 并发、OSS 故障、套餐到期、跨设备冲突与删除释放 |
| 管理员本地版意外请求 Dreamyo 云端 | 商业路由在本地代理层拒绝 | 构建时排除云模块、断网/抓包测试、逐页面直接 URL 验证 |

已通过的自动检查只覆盖现有 Web 测试、lint、类型与生产编译，以及 macOS arm64 上两个 Electron 开发壳的启动烟测。Web 的真实支付/积分回归、登录后 Canvas 完整浏览器矩阵、全部 Provider 成片、PostgreSQL 与 OSS 联调、跨架构打包安装和无依赖干净机验收仍须逐项执行。任何单个“健康接口 200”或“任务已提交”都不能代替结果文件与计费记录验收。
