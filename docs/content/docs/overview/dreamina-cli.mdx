# 即梦 CLI 命令与集成参考

本文依据本机 `dreamina -h` 与全部生成子命令 `-h` 的实际输出整理，核对日期为 2026-08-31，CLI 构建版本为 `673dd28-dirty`（commit `673dd28`）。供应商后端配置仍是最终约束；升级 CLI 后应重新执行本文末尾的帮助核对命令。

## 账号与异步任务

```bash
dreamina login
dreamina user_credit
dreamina list_task --limit=20
dreamina query_result --submit_id=<提交 ID> --download_dir=<绝对目录>
```

- `login` 使用 OAuth Device Flow；无头环境可用 `dreamina login --headless`，再执行 `dreamina login checklogin --device_code=<设备码>`。
- `user_credit` 返回 `total_credit`、`user_id`、`user_name` 和 `vip_level`。OctalFlow 只在管理员页展示脱敏用户 ID。
- 八个生成命令均为异步提交。OctalFlow 固定传入 `--poll=0`，保存 `submit_id`，由 Generation Worker 通过 `query_result` 恢复查询并下载结果。
- `list_task` 支持 `--gen_status`、`--gen_task_type`、`--limit`、`--offset`、`--submit_id`，用于查看当前登录账号已保存的任务。
- 当前 CLI **没有取消生成任务的命令**。`dreamina cancel -h` 返回 `unknown command "cancel" for "dreamina"`；`session delete` 只删除会话容器并把历史移回默认会话，不会取消生成任务。因此 OctalFlow 不向即梦任务声明上游取消能力：用户停止本地等待后，已提交任务仍可能继续消耗积分并在上游完成。

### 登录、退出与无头授权

```bash
dreamina login
dreamina login --headless
dreamina login checklogin --device_code=<设备码> --poll=30
dreamina logout
dreamina relogin
dreamina relogin --headless
dreamina user_credit
dreamina version
```

- 普通 `login` 会复用仍有效的本地 OAuth 状态，否则启动 Device Flow 并等待授权；`--headless` 只打印授权材料后退出。
- `login checklogin` 必须使用上一次无头登录返回的 `device_code`；`--poll=0` 只检查一次，正整数表示最多等待对应秒数。
- `logout` 只清除本地 OAuth 登录状态，不删除任务或配置；`relogin` 先清除状态，再强制启动新的 Device Flow。
- 管理页不会读取或展示 `device_code`、OAuth token 或 CLI 凭据文件，只执行状态查询并保存脱敏后的账号快照。

### 任务列表、查询与结果字段

```bash
dreamina list_task --gen_status=success --gen_task_type=text2image --limit=20 --offset=0
dreamina list_task --submit_id=<提交 ID>
dreamina query_result --submit_id=<提交 ID> --download_dir=<绝对目录>
```

`list_task` 默认最多返回 20 条，支持按 `gen_status`、`gen_task_type` 或 `submit_id` 过滤并用 `limit/offset` 分页。真实提交与查询结果中已经验证的关键字段如下：

| 字段                   | 含义                                                                    |
| ---------------------- | ----------------------------------------------------------------------- |
| `submit_id`            | 上游异步任务 ID，必须在返回给调用方前持久化                             |
| `gen_status`           | `querying`/`generating` 表示处理中，`success` 表示成功，`fail` 表示失败 |
| `result_json`          | 成功结果；媒体位于 `images`、`videos` 或 `audios` 数组                  |
| `result_json.*[].path` | 传入 `download_dir` 后的本地下载路径                                    |
| `credit_count`         | 本次任务的官方积分消耗；字段缺失时不得用旧余额猜测                      |
| `fail_reason`          | 明确失败原因；CLI 即使退出码为 0，也可能同时返回 `gen_status=fail`      |
| `queue_info`           | 上游排队信息，仅用于状态展示，不据此自行增加固定轮询或超时常数          |

`query_result` 的 JSON 与本地已下载文件是最终依据。成功响应可能返回多份媒体，OctalFlow 会全部登记和保留；不能只读取首份结果。

### 会话管理

```bash
dreamina session create "项目名"
dreamina session list -n 100
dreamina session search "项目名"
dreamina session rename 10086 "新项目名"
dreamina session delete 10086
```

- 所有生成命令都接受 `--session=<id>`；会话 0 是不能重命名或删除的默认会话。
- 会话名去除首尾空格后必须为 1–50 个字符。`session list` 默认读取 30 个，显式 `-n/--max-count` 上限为 100；`search` 在最近 100 个会话中做区分大小写的包含匹配。
- CLI 不提供置顶/取消置顶。删除会话是软删除并把历史移回默认会话，不会取消会话里的上游生成任务。

## 图片模型矩阵

| 模型版本                                 | 文生图 | 图生图 | 分辨率       | 备注                   |
| ---------------------------------------- | ------ | ------ | ------------ | ---------------------- |
| `3.0`、`3.1`                             | 支持   | 不支持 | 1K、2K       | 自定义宽高仅允许 2K    |
| `4.0`、`4.1`、`4.5`、`4.6`、`4.7`、`5.0` | 支持   | 支持   | 2K、4K       | 图生图最多 10 张参考图 |
| `5.0Pro`                                 | 支持   | 支持   | 1.5K、2K、4K | 图生图最多 10 张参考图 |

图片比例固定为 `21:9`、`16:9`、`3:2`、`4:3`、`1:1`、`3:4`、`2:3`、`9:16`。省略比例时默认 `16:9`。生成数量 `generate_num` 为 1–10，默认 1。

自定义宽高必须同时传入，且与 `--ratio` 互斥：

| 分辨率 | 单边范围  | 总像素上限 |
| ------ | --------- | ---------- |
| 1K     | 512–2016  | 1,763,584  |
| 1.5K   | 972–2268  | 2,359,296  |
| 2K     | 768–3072  | 4,194,304  |
| 4K     | 1536–6240 | 16,777,216 |

单边范围和总像素上限必须同时满足。宽高是目标值，模型可能做尺寸对齐，最终结果以 `query_result` 为准。

### `text2image`

```bash
dreamina text2image \
  --prompt="a cat portrait" \
  --model_version=5.0 \
  --ratio=1:1 \
  --resolution_type=2k \
  --generate_num=4 \
  --poll=0
```

参数：`--prompt`、`--session`、`--ratio`、`--resolution_type`、`--width`、`--height`、`--model_version`、`--generate_num`、`--poll`。`resolution_type` 必填；不使用比例时可以用精确宽高。

### `image2image`

```bash
dreamina image2image \
  --images=./input-a.png,./input-b.png \
  --prompt="turn into watercolor" \
  --model_version=5.0Pro \
  --ratio=4:3 \
  --resolution_type=1.5k \
  --generate_num=2 \
  --poll=0
```

参数与 `text2image` 相同，额外要求 `--images` 传入 1–10 张本地图片；模型不包含 3.0/3.1。

### `image_upscale`

```bash
dreamina image_upscale --image=./input.png --resolution_type=4k --poll=0
```

只接受一张本地图片，`resolution_type` 仅允许 2K、4K、8K。4K 和 8K 需要 VIP。OctalFlow 将它作为 Canvas“放大分辨率”的独立引擎，不作为普通生图逻辑模型。

## 视频模型矩阵

| 模型版本                                                                   | 文生视频 | 单图生视频 | 首尾帧 | 全能参考 | 清晰度            | 时长         |
| -------------------------------------------------------------------------- | -------- | ---------- | ------ | -------- | ----------------- | ------------ |
| `seedance1.0fast`                                                          | 否       | 是         | 否     | 否       | 720P              | 5–10 秒      |
| `seedance1.5pro`                                                           | 否       | 是         | 是     | 否       | 720P              | 5–12 秒      |
| `seedance2.0`、`seedance2.0fast`、`seedance2.0fast_vip`、`seedance2.0mini` | 是       | 是         | 是     | 是       | 720P              | 4–15 秒      |
| `seedance2.0_vip`                                                          | 是       | 是         | 是     | 是       | 720P、1080P、4K   | 4–15 秒      |
| `seedance2.5`                                                              | 是       | 是         | 是     | 是       | 480P、720P、1080P | 4–30 秒，VIP |

视频比例固定为 `1:1`、`3:4`、`16:9`、`4:3`、`9:16`、`21:9`。只有文生视频和全能参考显式接受比例；单图生视频、首尾帧和多帧视频从输入图片推断比例。

部分模型首次使用前，需要先在即梦 Web 端完成一次生成确认。CLI 返回 `AigcComplianceConfirmationRequired` 时，应转为待处理状态，不能自动重试。

### `text2video`

```bash
dreamina text2video \
  --prompt="a cat running" \
  --model_version=seedance2.0fast \
  --duration=5 \
  --ratio=16:9 \
  --video_resolution=720p \
  --poll=0
```

参数：`--prompt`、`--session`、`--duration`、`--ratio`、`--video_resolution`、`--model_version`、`--poll`。不支持 1.0fast/1.5pro。

### `image2video`

```bash
dreamina image2video \
  --image=./first.png \
  --prompt="camera push in" \
  --model_version=seedance2.0 \
  --duration=5 \
  --video_resolution=720p \
  --poll=0
```

`--image`、`--prompt`、`--video_resolution` 必填；比例由图片推断。支持完整视频模型集合。

### `frames2video`

```bash
dreamina frames2video \
  --first=./start.png \
  --last=./end.png \
  --prompt="season changes" \
  --model_version=seedance2.0mini \
  --duration=5 \
  --video_resolution=720p \
  --poll=0
```

`--first`、`--last`、`--prompt`、`--video_resolution` 必填，首尾帧不能使用同一素材；不支持 1.0fast。

### `multiframe2video`

两张图片使用简写：

```bash
dreamina multiframe2video \
  --images=./a.png,./b.png \
  --prompt="character turns around" \
  --duration=3 \
  --video_resolution=720p \
  --poll=0
```

三张及以上图片为每个转场重复参数：

```bash
dreamina multiframe2video \
  --images=./a.png,./b.png,./c.png \
  --transition-prompt="turn from A to B" \
  --transition-prompt="turn from B to C" \
  --transition-duration=3 \
  --transition-duration=4 \
  --video_resolution=1080p \
  --poll=0
```

图片数量 2–20，清晰度只允许 720P/1080P，模型固定且不能传 `model_version`。N 张图必须有 N−1 个转场提示词；转场时长每段 1–8 秒，省略时每段默认 3 秒，总时长至少 2 秒。

### `multimodal2video`

```bash
dreamina multimodal2video \
  --image=./input.png \
  --video=./reference.mp4 \
  --audio=./music.mp3 \
  --prompt="turn this into a cinematic shot" \
  --model_version=seedance2.0fast \
  --duration=5 \
  --ratio=16:9 \
  --video_resolution=720p \
  --poll=0
```

- 图片、视频和音频分别通过重复的 `--image`、`--video`、`--audio` 传入。
- Seedance 2.0 系列至少需要一张图片或一个视频；图片最多 9、视频最多 3、音频最多 3，总素材最多 12，单个及总视频/音频时长 2–15 秒。
- Seedance 2.5 允许纯音频；图片最多 30、视频最多 10、音频最多 10，总素材最多 50，单个及总视频/音频时长 2–30 秒。

## OctalFlow 中的模型启用与参数联动

1. 在 `管理员后台 → 上游配置 → 即梦 CLI` 点击“刷新状态”。只有 CLI 已安装且账号授权有效时，才能新启用模型；授权失效时仍可清空已启用模型。
2. 模型配置页可分别启用 Seedream 3.0/3.1/4.0/4.1/4.5/4.6/4.7/5.0/5.0 Pro，以及 Seedance 1.0 Fast/1.5 Pro/2.0 系列/2.5。
3. 保存后，普通生成模型同步为 `dreamina-cli` 渠道绑定的逻辑模型；关闭某模型会移除对应逻辑绑定，因此它不再出现在 Canvas 模型选择器。
4. Canvas 根据当前模型和参考素材切换合法选项：Seedream 分辨率、Seedance 清晰度/时长、文生/图生/首尾帧/全能参考的可用模型，以及是否由参考图锁定比例。
5. `image_upscale` 和固定模型的 `multiframe2video` 是操作型能力，必须单独启用；前者只在图片放大弹层显示，后者只在多图视频路径使用。
6. “调用统计”默认显示累计官方积分消耗，也可切换本周、本月和本年；自然周期按系统时区（默认 `Asia/Shanghai`）计算，同一 `submit_id` 在提交与查询日志中只累计一次。

OctalFlow 使用固定参数构造器和 `execFile` 执行 CLI，不接受浏览器传入子命令或任意 argv，不读取 CLI 的 OAuth 凭据文件，也不把本地路径、提示词、设备码或原始 stdout/stderr 写入管理员日志。

## 积分记录规则

优先级如下：

1. 2026-08-31 的真实 `text2image` 提交响应包含 `credit_count`，实测值与账号余额变化一致。OctalFlow 直接把它记录为官方逐单积分，不再为每条任务调用两次 `user_credit`。
2. `user_credit` 只在管理员点击“刷新状态”时同步账号余额、授权和会员快照；它不是逐单积分来源。
3. 旧版本留下的余额差观测仍可读取并明确标记来源；新提交若缺少 `credit_count`，日志只标记为不可用，不使用过期余额猜测成本。
4. CLI 返回已提交但响应无法解析时，任务进入 `needs_review`，禁止自动重试、渠道回退或自动退还平台积分，避免重复扣费。
5. 后台时间范围统计只把官方 `credit_count` 显示为“积分消耗”；请求数、成功数、失败数和待确认数使用同一时间窗口。PostgreSQL 由数据库直接聚合，文件模式使用相同的半开时间区间，不把全量日志传给浏览器计算。

## 真实兼容性验收

2026-08-31 使用当前已登录账号完成了以下真实调用。图片覆盖不同模型、比例、分辨率、自定义宽高、双参考图和图片超清；视频严格只使用非 VIP 模型。

| ------------------ | ------------------------------------- | ------------------------------ | -------------- |
| `text2image`       | 3.0 / 1K / 1:1 / 4 张                 | 成功，返回 4 张 1328×1328 图片 | 1              |
| `text2image`       | 4.0 / 2K / 16:9                       | 成功，2560×1440                | 本次响应未返回 |
| `text2image`       | 4.7 / 4K / 9:16                       | 成功，3040×5404                | 2              |
| `text2image`       | 5.0 Pro / 1.5K / 4:3                  | 成功，1728×1296                | 本次响应未返回 |
| `text2image`       | 5.0 / 2K / 自定义 2048×1536           | 成功，上游对齐为 2218×1663     | 本次响应未返回 |
| `image2image`      | 5.0 Pro / 双参考图 / 2K / 3:4         | 成功                           | 8              |
| `image_upscale`    | 2K                                    | 成功，2160×2160                | 1              |
| `text2video`       | Seedance 2.0 / 720P / 1:1 / 4 秒      | 已接收并持续排队               | 12             |
| `image2video`      | Seedance 2.0 Fast / 720P / 5 秒       | 已接收并持续排队               | 10             |
| `frames2video`     | Seedance 2.0 Mini / 720P / 4 秒       | 成功，960×960 / 4.042 秒       | 24             |
| `multiframe2video` | 固定模型 / 720P / 2 秒                | 成功，960×960 / 2.208 秒       | 4              |
| `multimodal2video` | Seedance 2.0 Fast / 720P / 4:3 / 4 秒 | 高峰期明确拒绝，未创建计费任务 | 无             |

`frames2video` 成功结果还通过 `query_result --download_dir` 下载为 3,024,145 字节的本地 MP4，验证了 OctalFlow 读取本地结果路径的契约。`query_result` 偶尔会暂时返回 `get_history_by_ids failed: ret=1015`；这是只读查询的可重试错误，Generation Worker 会延后再查，不会把已接收任务误判为 `needs_review` 或重复提交。

本轮没有调用 `seedance2.0_vip`、`seedance2.0fast_vip` 或 `seedance2.5`。VIP 模型只验证了参数目录和权限约束，没有产生真实视频费用。
