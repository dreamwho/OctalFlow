## 3. 证据完整性与发现

提交前使用自写临时请求保护，要求model、duration、ratio与一张已上传图片完全匹配，原生body不做修改；同case重复创建被拦截。生成期间只刷新原会话以取得异步结果，没有重新点击发送，也没有换号。页面刷新后临时保护随页面生命周期清除。

**本次HAR保留了创建响应，但没有保留该创建请求的postData。** 参数证据来自实际发送前的功能字段日志，以及原会话服务端 `ext.chat_ability` 回显，二者一致。不能将这一样本写成“完整HTTP请求body已抓到”。附件以同一原会话用户消息中的10052块核对；用于实现的完整body基准仍参考06的已有完整样本，并在隔离反代测试中再捕获独立完整请求。

上传另有补充事实：从浏览器保留的早前记录追回了纸船参考图的二进制上传，实际为 `POST` 到 `tos-myb1-share.vodupload.com`，HTTP200；`Content-CRC32` 为八位十六进制，使用标准库zlib计算与该PNG一致。**不能沿用参考仓库猜测的TOS PUT。** 该记录属于早前那次上传；Fast请求回显的图片URI不同，不能声称这一次复用了同一个上游资源，Fast本次二进制传输没有独立导出。

结果中的 `gen_detail.ref_images` 可为空，但本样本已成功使用图片。不能只据该字段为空就判断上传失败或退回文生视频。相同视频对象可能在消息的结构字段和序列化JSON中重复出现，解析器应按稳定creation/vid去重，不能把递归遍历的三份对象当作三条成片。
