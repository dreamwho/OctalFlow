# Dola 真实页面对照与登录态协议

## 固定开发方法

后续 Dola 协议优化、修复、补充和复测都使用同一闭环：

1. 使用已导入 Cookie 在真实 `https://www.dola.com/chat/create-image` 页面复现状态。
2. 保存最终 URL、页面文字、截图及对应网络请求；页面是状态事实基准，后台旧标签不是判断依据。
3. 对真实请求做 HTTP 重放，逐项删除签名、动态参数和非必要请求头，得到最小可行协议。
4. 将协议封装到 Provider，并用同一账号分别执行浏览器请求与纯 HTTP 请求，结果一致才算通过。
5. 日常批量检测优先使用轻量 HTTP 协议；结果不明确、协议漂移或出现结构化安全挑战时才进入可见 Camoufox 诊断。

## 登录态实测结论

Dola AI 创作页启动时会发送：

```text
POST /alice/user/launch
```

请求体为：

```json
{
  "select": {
    "launch_config": true,
    "assistant_bot_info": true,
    "landing_config": true,
    "user_info": true
  }
}
```

页面中出现登录窗口的账号返回：

```json
{"code": 0, "data": {"extra": {"is_login": "0"}}}
```

真实已登录账号返回：

```json
{"code": 0, "data": {"extra": {"is_login": "1"}}}
```

实测将浏览器请求中的 `a_bogus` 删除后，HTTP 重放仍返回相同登录态。协议只需要 Cookie、普通 Web 身份查询参数和上述请求体，因此批量登录检测不需要启动 Camoufox。

## 判定规则

- `code=0` 且 `is_login=0`：`needs_login`，账号退出生成轮询。
- `code=0` 且 `is_login=1`：登录态有效，继续执行页面签名和只读协议可用性检查。
- HTTP 异常、非零业务码或字段缺失：`unknown`，不得猜测为登录失效或滑块验证，进入 Camoufox 对照诊断。
- 页面出现登录窗口、登录按钮或跳转 `from_logout=1`：作为 `needs_login` 的浏览器证据，与启动协议结果一起记录。
- 只有上游返回结构化挑战并捕获验证会话时才标记 `verification_required`；普通错误码不得推断为滑块。

## 资源策略

批量账号检测不读取后台旧状态作为跳过条件。所有已启用 Cookie 先执行 HTTP 登录态检测；已失效账号无需创建浏览器。登录正常或结果不明确的账号再进入完整协议验证，并按 Provider 浏览器资源限制控制并发。
