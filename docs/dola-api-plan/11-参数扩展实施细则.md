# 两模型、时长、比例与图片参数的实施细则

本页是已执行开发计划的参数合同。最新请求证据和用户验收范围以10为准；其中2.5本次3:4单图原生媒体现已核验，独立HTTP创建仍受13所述验证流程阻塞。这里的15/30秒示例表示已加入能力目录并待真实上游成片验收的请求，不表示长时长已经生成成功。

## 1. 需求与证据分开存放

| 站内模型 | 上游模型值 | 原生时长 | 目标扩展 | 目标比例 |
| --- | --- | --- | --- | --- |
| `dola-seedance-2-5` | `seedance_v2.5` | 5、10秒 | 15、30秒 | 1:1、3:4、4:3、9:16、16:9、21:9 |
| `dola-seedance-2-0-fast` | `seedance_v2.0` | 5、10秒 | 15秒，上限15秒 | 1:1、3:4、4:3、9:16、16:9、21:9 |

两份独立profile分别写`durationOptions:[5,10,15,30]`和`[5,10,15]`；目录的离散`durationRange`分别写`"5,10,15,30"`和`"5,10,15"`。禁止用区间`"5-30"`让所有整数都变成公开选项。两份`aspectRatios`目前相同，仍需独立绑定模型，不能加到所有渠道的全局默认值。

能力证据按模型/输入方式/时长/比例组合记录`observed / submitted / verified / blocked / untested`及caseId。原生菜单配置证明选项存在，实际媒体证明对应组合成功；不得把单条证据扩散为整个笛卡尔积已验证。

## 2. 两类参考扩展实际做了什么

`dola-30s-unlocker-main/hook.js`的`patchAnyDuration`递归访问普通对象和嵌套JSON字符串，给`option_list/options/supported_durations`增加30秒。它主要改变网页可选项；包含旧模型ID，不能直接当作当前2.5请求模板。前端能选30不证明上游已出30秒。

`admin0x/doubaokit`固定审查commit为`dcf7041c87fa3b7153edd2fddc5d7b6bd238a811`。`doubao-kit.js`的`modifySeedanceRequestBody`查找`ability_param`附近的`duration`并替换；其600字符扫描窗口只是扩展实现细节，不是协议要求。该项目的提示词还声称“额度等于秒数”并引导旧规则，这些没有实际余额接口或成片证据，不能作为本项目的额度合同或必要协议步骤。

因此本项目直接在自己的能力目录增加离散选项，在Provider编译结构化请求时写入时长。无需用户安装扩展，无需篡改网页显示，无需把参考扩展的正则、旧ID、提示词规则或最近档位强制转换复制进服务端。许可证与独立实现边界见01/07。

## 3. 参数从Canvas到Dola的完整路径

```text
Canvas当前逻辑模型 + 参数弹层
  → 配置节点metadata和生成快照
  → 现有默认文本模型规划（遵守用户显式参数优先级）
  → 逻辑模型binding.capabilityProfile
  → 服务端Dola模型参数校验
  → generation_tasks请求快照 + Dola attempt
  → 选定账号内上传图片
  → Provider完整原生请求模板
  → chat_ability.ability_param（JSON字符串）
  → 一次/chat/completion → SSE ACK → 原会话查询 → 原媒体
```

拟新增`web/src/lib/server/dola/catalog.ts`负责两模型profile；`prompt-compiler.ts`负责站内引用序号和执行文字，`reference-service.ts`负责账号内资源映射。`services/dola-api/src/dola_api/protocol.py`负责原生body编译；`transport.py`只发送已编译body；`sse.py`只解析事件。实现路径及现有修改文件见04的T02、T05—T07，不新增第二套Canvas参数状态。

拟定义的站内输入例子：

```json
{
  "logicalModelId": "dola-seedance-2-5",
  "durationSeconds": 30,
  "aspectRatio": "3:4",
  "prompt": "让参考图中的主体缓慢漂动，保持主体外观和固定镜头",
  "references": [{"assetId":"<OWNED_ASSET>","role":"reference","ordinal":1}]
}
```

Provider最终功能字段例子（仅此对象，完整body还需当前会话上下文）：

```json
{
  "ability_type": 17,
  "ability_param": "{\"ratio\":\"3:4\",\"model\":\"seedance_v2.5\",\"duration\":30,\"camera_movement\":\"fixed\",\"input_box_content\":{\"user_input_content\":\"让参考图中的主体缓慢漂动，保持主体外观和固定镜头\",\"reply_message_format\":\"生成视频：%s\"}}"
}
```

实施伪代码，使用语言标准JSON库：

```python
profile = model_profiles[request.logical_model_id]
validate_duration(request.duration_seconds, profile.duration_options)
validate_ratio(request.aspect_ratio, profile.aspect_ratios)
body = build_current_session_body(session, attempt, uploaded_references, prompt)
ability = json.loads(body["chat_ability"]["ability_param"])
ability.update(model=profile.upstream_model_id,
               duration=request.duration_seconds, ratio=request.aspect_ratio)
body["chat_ability"]["ability_type"] = 17
body["chat_ability"]["ability_param"] = json.dumps(ability, ensure_ascii=False)
return body
```

`build_current_session_body`必须来自T02验证后的完整模板，不能把上述示例当作最小可运行body。保留`camera_movement`、`input_box_content`及当前有效原生上下文；动态生成稳定的本次local ID、消息ID、unique_key和时间。Cookie、CSRF、设备和上传授权从当前隔离会话获取，不写死研究账号数据。只做参数修改时，10052图片附件、10000文字块、图片URI和上传状态不能被重建丢失。

本轮2.5完整请求的`messages`有两项：一项10052图片块，一项10000文字块。`[10052,10000]`是跨消息的块类型摘要，**不是要求把两个块强行塞进同一条messages元素**。完整原生结构应在fixture中保留；同理不能认为只传图片URL给模型就能图生。

## 4. 比例设置与参考图比例冲突

比例写入`ability_param.ratio`，不能只拼“3:4”进提示词。当前参考图为960×540（16:9），本次明确选择3:4，因此用户本轮显式比例覆盖参考图比例；参考图用于内容条件，不能把输出自动改回16:9。

Canvas继续沿用`resolveLogicalModelCapabilityProfile()`。两个模型当前都支持六档时保留所选比例；用缺少某比例的测试profile验证切换后提示重选，不能隐藏地沿用非法值。服务端独立校验。精确像素输入按02 §3.3保存用户意图，Dola只支持比例时不承诺像素精确控制，不裁切或缩放生成文件来制造通过。

验收需同时断言UI选项、配置metadata、生成任务快照、原生请求的ratio、FFprobe实际宽高比。封面缩略图宽高、助手文字和播放器容器尺寸都不能代替文件实际宽高。

## 5. 时长扩展的错误与发布行为

1. 显式Fast30秒在入队前返回中文422；2.5的30秒切到Fast必须重选。不要让通用归一化函数先截成15。
2. 用户非标准12秒沿用项目已有归一化策略到15，但必须保留原始意图和最终实际档位；如该模型档位未开放，则返回明确原因。
3. 上游明确额度不足且未受理时，才按调度合同考虑其他可用账号；已ACK或结果未知不换号重新创建。
4. 时长/模型不支持的错误原样映射，不自动把30改10重发，不拼接、不慢放、不补帧。
5. 15/30通过管理员真实测试获得媒体后开放相应生产能力；完整需求交付必须包含Fast15与2.5的15/30。此前界面可在管理员测试窗口标记“待实测”，不能向普通用户宣称已验证。
6. 5秒成功足以形成可实施的协议设计；10秒与长时长仍有各自测试状态。Fast10秒已有文生证据，不能据此声称两模型10秒图生均已验证。

## 6. 最小回归与任务归属

| 所属任务 | 必须断言 |
| --- | --- |
| T02协议编译 | 两模型wire ID准确；ability_param标准JSON字符串；保留图片块与会话结构；不依赖600字符窗口；中文正常 |
| T06能力目录 | 2.5四档、Fast三档分别保存/读取；六比例分别绑定；普通用户只拿公开模型及已开放能力 |
| T07 Canvas | 2×6比例正常点击、持久化；2.5的30切Fast阻止提交；16:9参考图显式3:4不被覆盖 |
| T05持久任务 | 创建只一次；媒体异步晚到可恢复；ratio/duration和账号快照不随后台配置变化 |
| T09测试窗口 | 可选账号/模型/比例/时长/单图；明确预计会消耗上游额度；日志与普通任务共用 |
| T14真实验收 | 复用Fast5秒单图与既有文生媒体；2.5本次3:4已取得720×960/5.041667秒原生媒体及参考图证据，可以复用该样本；新增隔离环境与长时长测试需明确预算；每次只改必要变量并记录实际媒体 |

离线fixture测试不消耗额度；真实测试只在用户授权的范围内执行。用户先接受2.5单图请求并停止持续跟踪，后报告成功，已复核原片；没有因此自动再发10、15或30秒请求。
