# 滑块验证处理、原会话恢复与补测任务

日期：2026-09-16。状态：**Provider 同页验证会话、租约、截图、指针输入、恢复/关闭路由及 Canvas 受限弹层已实现；尚未完成一次真实滑块人工通过的生产 Case。** 最新[15](15-IPWO直协议与Camoufox-Cookie会话实测.md)已证明用户Cookie可在全新Camoufox context中提交Fast5秒单图并取得ACK且无滑块，因此主transport改为Camoufox原生页面会话；本页不再是主链路启用前的阻塞条件，但仍是生产环境再次出现挑战时必须具备的恢复能力。Canvas任务所有者方案见[14](14-新账号HTTP复测与Canvas人工验证.md)，当前已接入应用。

## 1. 本次查明的官方处理方法

本次只读取 Dola 当前页面引用的第一方静态脚本；没有新增视频提交，也没有为获得新挑战而重发创建。脚本 URL、SHA-256、定位词和证据等级见[官方验证代码证据](evidence/live/verification-sdk-source.sanitized.json)。压缩文件行号不稳定，接手者用文件哈希及函数名定位，不复制整份第三方 bundle。

| 层次 | 已确认事实 | 对实现的影响 |
| --- | --- | --- |
| 已实测错误 | HTTP200，STREAM_ERROR 710022004，`extra.decision` 内 `type=verify, subtype=slide`，没有 SSE_ACK/任务 ID | 必须解析业务事件并进入待验证；不能当额度耗尽或生成成功 |
| Dola 应用处理器 | `MessageLimitSharkVerifyMessageErrorPlugin.handleSendingMessageError` 从消息错误的 `error_details.extra_info.decision` 取完整 decision | HTTP 适配器保留原始 decision 在受控内存/密文中；不能把其中 `detail` 当验证 URL |
| 官方弹窗 | 处理器取 `initTTVerifyCenterInstance()` 和 `getFPForVerifyCenter()`，调用实例 `render({verify_data: decision, captchaOptions: ...})` | 使用原会话官方验证环境；`verify_data` 是完整结构，不自行拼验证链接 |
| 应用初始化 | 当前模块以 commonOptions 和当前 fp 初始化 `TTVerifyCenter`，`showMode="mask"` | aid、repoId、fp、地区及官方 SDK 版本都属于当前会话合同，不能移植研究账号固定值 |
| 回调 | `captchaOptions.successCb / errorCb`；底层 SDK 另有 `closeCb` | 处理成功、错误、关闭三种状态；构造器的“SDK 初始化成功”回调不等于挑战成功 |
| 原生重发 | 应用的挑战 successCb 调用消息 retry handler，再执行该 handler | **完成官方验证可能立即重发原消息**；不能再由 Worker 同时重发 |
| SDK 能力 | `TTVerifyCenter.render()` 交给官方实例 autoRender；底层成功回调可携带 headers 和 replay_data | 不假定只拷贝 Cookie 即可恢复；这些输出必须保密、绑定原挑战，具体 HTTP 用法尚待验证 |
| 通用 XHR 拦截 | SDK 存在识别 `bdturing-verify` / `x-vc-bdturing-parameters` 后验证并重放 XHR 的功能 | 这是静态代码能力，**尚未证明本次 SSE 路径使用该拦截器**；不能无条件开启 |

源代码证据说明有正常验证入口和原生重发行为，不证明本次已弹出或解决挑战。旧 HTTP 测试的私有原始挑战已清理，脱敏 fixture 不能生成可用挑战。下一次真实闭环必须取得仍有效的官方挑战；不能用已失效数据制造“通过”。

## 2. 产品行为与自动化边界

采用“自动识别 → 官方窗口供授权操作者操作 → 自动核实会话 → 安全恢复原请求”的流程。滑块由管理员或当前任务所有者在官方界面完成；识别、暂停、会话同步和恢复编排由系统负责。当前方案不宣称无人值守自动解滑块，也不以换号、换出口或伪造轨迹替代官方验证。

1. 请求日志显示“需完成 Dola 验证”，账号显示“待验证”。保存 request/attempt 关联，不追加新的 Canvas 生成节点。
2. 管理员在账号行、请求详情或测试窗口点击“处理验证”；Canvas任务所有者在原视频节点点击“完成验证”。各入口关联同一个验证会话，普通用户仅获14规定的挑战区域控制权。
3. 展示官方挑战及账号别名、模型、时长、比例；仅展示当前验证必需内容，不展示凭据和原始风控数据。
4. 官方成功后显示“验证已完成，正在核实原请求”。读到原任务则继续查询；具备明确未受理和授权条件时才恢复创建。
5. 用户关闭窗口仅断开交互视图，不自动重发、不伪称取消上游任务。原挑战过期则显示“验证已失效”；刷新验证与重新生成是不同操作。
6. Canvas任务所有者可按14打开受限官方挑战Modal，完成后继续原节点；不能向普通用户暴露完整账号浏览器、凭据或聊天记录。无法限制挑战区域时再交管理员处理。

本页初次调研没有新增创建；后续新账号C一次复测见14。B账号4/4、C账号1/1各自记账，本页静态研究不增加额外生成。人工完成验证可能触发原生重发，这项额度影响也必须纳入下一轮测试授权。

## 3. 会话环境：本机与服务器都必须可处理

验证绑定 `accountId + credentialVersion + proxyTarget/proxyUrl + contextId + attemptId`。从图片上传、创建、挑战到查询保持原账号和原出口；挑战等待期间固定 context，不把它回收后随便开一个新页面冒充同一会话。`proxyTarget` 只引用现有通用代理管理的节点或分组，历史报告中的 `proxyRevision` 仅是当时实验命名。

- **本机部署**：Provider 打开自己管理的原账号浏览器窗口，管理员在此窗口完成验证。不能打开个人 Chrome 的另一个账号后直接标记服务器账号成功。
- **Linux 部署**：Dola后台Drawer或Canvas受限Modal展示Provider原context中官方挑战的交互视图；Canvas只允许14所规定的挑战区域。现有 `services/geminiai/.../account/login_service.py` 提供有头/终端登录思路，但本次定向检查没有找到可直接复用的远程滑块视图，不能把“复制 Google 页面”当作已经具备远程验证。
- **具体首版方案**：复用 Playwright 原 page，通过受鉴权的 SSE 发送挑战区域图像，通过 POST 回传管理员 pointer down/move/up、必要的键盘和关闭操作。截图使用 Playwright，UI 使用现有 React/Ant Design，不给浏览器开放任意 JS 执行、任意 URL 导航、系统剪贴板或文件操作。
- 交互视图只映射真实人工输入，不生成拖动轨迹。每个输入包含 `controlLeaseId / sequence / viewportRevision`，服务端拒绝过期租约和乱序事件；移动事件可在绘制帧内合并，但 down/up 不丢失。关闭/断线必须释放按下状态。
- 帧率、会话闲置期限和资源限额使用管理员明确配置或项目已有合同，不能写死随意轮询次数。没有前台控制者时停帧；验证状态继续由 Provider 真实事件驱动。若 SSE 图像流在目标网络中无法支撑真实拖动，T02-V 必须修正传输并重新验收，不能只用静态截图判成功。
- 通过 Next.js 服务端代理到私网 sidecar；SSE 可由 Route Handler 转发，本计划**不假定 Next.js Route Handler 可以直接实现 WebSocket upgrade**。如改 WebSocket，须明确反向代理/独立服务入口及鉴权后再替换。
- 不直接在管理页 iframe 嵌入 dola.com：跨域、Cookie 隔离、CSP 和服务器会话归属都不能据此解决。官方 SDK 必须在匹配的 Dola 浏览器上下文中工作，不能把挑战凭据发到普通管理页执行环境。

同一账号同一时刻只允许一个有效验证控制租约；其他管理员可查看脱敏状态。账号禁用/删除、管理员退出、凭据替换或代理 revision 改变时撤销旧控制权。进程重启无法恢复活的 page 时标记 `context_lost`，保留待核实请求，不自动新建生成。

## 4. 两条恢复路径只能选一条负责重发

### 4.1 browser-session：官方消息处理器负责恢复

在开放可交互验证视图之前，必须取得本业务请求的恢复授权并原子预留一次恢复dispatch；没有授权时只提供状态查看，因为完成挑战可能立即触发官方重发，不能等successCb之后才询问是否创建。恢复授权属于现有用户生成请求的产品合同，但本次研究的四次预算已用完，不能套用为新增测试许可。

真实创建经受控原生页面发出时，让官方错误处理器呈现挑战。为本次 attempt 记录 `resumeOwner=official-page`，Provider 只观察原消息及其重发的网络证据，不再调用发送按钮、自己的 HTTP 创建器或第二个 retry handler。

验证成功后，官方 successCb 会取得 retry handler 并调用。Provider 必须把此次重发登记为**同业务 request 下新的 dispatch/attempt 记录**，与原失败尝试和 challenge 关联；不能将网络 POST 数量写成一次。页面侧的重发也须消耗已有请求的恢复授权和额度预算。任何重复成功回调、重复管理员点击或 Worker 恢复都不能再额外创建。

若无法观察/限制原生重发或将其和原请求准确关联，browser-session 验证恢复不通过 T02-V；不能仅凭弹窗消失开放生产。

### 4.2 http-session：受控服务负责恢复

独立 HTTP 创建遭遇 decision 时，由受控浏览器内正常初始化的官方验证实例只负责展示、交互与收集验证结果，记录 `resumeOwner=service`。**不要同时调用 Dola 消息错误插件**，因为该插件 successCb 会自动重发。

以下仅说明调用形状，`officialInstance` 不是已暴露的稳定公共 API，`currentSessionFp` 不是可硬编码值；实例取得、地区配置和调用点必须在 T02-V 用当前页面版本确认。不要复制压缩 webpack 模块 ID 作为永久接口。

```ts
// 待实施契约示意；运行于匹配账号的受控 Dola 页面。
officialInstance.render({
  verify_data: originalDecision,
  captchaOptions: {
    fp: currentSessionFp,
    showMode: 'mask',
    successCb: (result, replay) => reportVerificationResult(result, replay),
    errorCb: error => reportVerificationError(error),
    closeCb: () => reportVerificationClosed(),
  },
});
```

`reportVerificationResult` 是拟实现的受控桥接函数，不是网页提供的 API。只接收此 page、此 challenge 的事件，经内部服务身份和 leaseEpoch 校验，不能由管理页发送 `{success:true}` 直接置成功。原始输出仅存 Provider 内存；必要恢复数据加密短存，日志仅保留结果类别。

随后同步当前 context 的 Cookie/storageState 及官方明确返回的会话数据。headers/replay_data 的具体消费方式必须依据实际成功后的请求差异验证；不自行猜字段名、头名或固定签名。不保证一次验证永久免验证，也不能用只读接口200证明创建恢复。

若 HTTP 请求绑定的设备/会话无法在该 context 正常验证，记录具体失败并保持阻塞。不能自动降为 browser-session 后再宣称“纯 HTTP 验证通过”。两种 transport 有各自验收记录。

### 4.3 恢复创建前的共同检查

1. 先核对原请求是否受理：有精确上游身份就查询原会话/消息/任务；无身份、无明确拒绝则为 `outcome_unknown`。查询列表没有发现结果，不足以证明未受理。
2. 本次已见 710022004 无 ACK，但尚未证明上游幂等或扣量合同；禁止把无 ACK 一概当可安全重发。需保留此不确定性并在真实恢复测试中核实。
3. 明确失败且管理员选择恢复时，同 `requestId / generationTaskId / CanvasNodeId` 保持不变，新建关联 challenge 的 attempt，使用受控 CAS 领取 dispatch 权；消息 ID 如何沿用以官方重发样本为准，不能自行宣称沿用 unique_key 就一定幂等。
4. 服务端复核账号、凭据/代理版本、任务取消状态、授权范围及可知额度；额度未知显示未知，不从上次“剩余1”推定当前可用。
5. resumeOwner 决定唯一创建责任方。记录创建发生前后的 attempt、受理 ID、额度来源与媒体；不得只以最终页面出现视频判断没有重复请求。
6. 受理后中断只恢复查询；下载失败只重试保存；验证重复失败返回待处理，不写固定次数循环撞上游。

## 5. 持久数据、状态与接口合同

新增专用 `dola_verifications`（计划第九张 Dola 表），不把私有挑战塞入公开日志或批量 operation 明细。同步02的数据表、数据库文档、PostgreSQL/JSON provider 和备份白名单。

字段：`id, account_id, attempt_id, credential_version, proxy_target_snapshot, context_id, provider_instance_id, lease_epoch, state, resume_owner, challenge_fingerprint, challenge_ciphertext, upstream_expires_at, policy_expires_at, controller_user_id, control_lease_hash, control_lease_until, version, created_at, updated_at, completed_at`。

- attempt_id 唯一；同一次响应重复写入返回同一 challenge。有效账号验证按账号/state定向查，不全表读入内存。
- challenge_fingerprint 使用 HMAC；challenge_ciphertext 包含必要的 decision 和私有恢复数据，采用现有加密工具，绝不保存明文。原始对象只可被当前内部 Provider 解密。
- expiresAt 优先尊重上游明确期限；无期限时为 null，再受管理员配置的会话保留期控制。过期/完成清理密文，审计只保留匿名关联及状态。
- 控制租约 token 仅返回给当前管理员会话一次且仅保留内存，服务端存 hash；通过请求头携带，禁止拼查询 URL 或进入 localStorage。

验证状态：`required → opening → waiting_for_user → verifying → verified`；分支 `failed / expired / cancelled / context_lost`。`verified` 只证明挑战成功，生成 attempt 仍需 `reconciling → accepted / explicitly_rejected / outcome_unknown`。账号状态只有复核后才从 verification_required 转 ready，禁用开关始终独立优先。

Canvas普通用户的任务绑定路由及更窄控制范围按14 §3实现，不能直接复用管理员接口的权限。

以下都是**拟新增项目接口**，不是 Dola 官方路径。使用管理员 Session + `upstream.manage`，响应保持 `{code,data,msg}`；没有密码/TOTP二次确认。

| 方法及路径（`/api/admin/dola` 下） | 输入/输出及副作用 |
| --- | --- |
| GET `/verifications?accountId=&state=&cursor=` | 分页脱敏状态、关联请求、能否打开/恢复；无 decision、Cookie 或原始SDK结果 |
| GET `/verifications/:id` | 状态、revision、已知期限、resumeOwner、是否存在原上游身份 |
| POST `/verifications/:id/open` | body.expectedVersion；领取控制租约并呈现已有挑战；重复打开不能生成新视频 |
| GET `/verifications/:id/frames` | 授权控制租约下 SSE 图像帧；no-store、断开即释放传输资源 |
| POST `/verifications/:id/input` | 有序真实人工输入；校验租约/viewportRevision/允许动作；不接受任意脚本 |
| POST `/verifications/:id/close` | 释放控制权及鼠标状态；保持真实挑战/请求状态，不重新创建 |
| POST `/verifications/:id/reconcile` | 查询原任务及会话，绝不创建视频；前端不能传“验证成功” |
| POST `/verifications/:id/resume` | expectedVersion + clientRequestId；服务端检查恢复条件，CAS创建一次新attempt；official-page模式仅批准/观察其单次恢复，不再单独POST创建 |

内部 Provider 新增 `/internal/verifications/{id}/open|input|close|reconcile`、帧流与受控验证事件回传。沿用02内部服务认证/事件seq/leaseEpoch；不得把内部服务密钥返回浏览器。SSE转发和输入请求均校验 origin、同一管理员、权限及控制租约，反向代理禁止缓存图像流和记录令牌。
