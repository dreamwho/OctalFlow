## 3. 已经核实的协议事实

### 3.1 两个模型的真实 ID

| UI 名称 | 当前真实 wire ID | 证据 |
| --- | --- | --- |
| Dreamina Seedance 2.5 | `seedance_v2.5` | action bar 的 `option_key`、`extra.model`；真实 `/chat/completion` 请求 |
| Dreamina Seedance 2.0 Fast | `seedance_v2.0` | action bar 的 `option_key`；真实 `/chat/completion` 请求 |

这是当前账号、当前页面版本实测所得，不再是名称猜测。两个 ID 不能混用；特别是 `dou3bao3` 把所有模型归一化到 `seedance_v2.0` 会丢失 2.5 选择。

### 3.2 当前能力来源存在两套配置

1. `POST /alice/slot/action_bar_v3/get_item_conf`，HTTP 200。响应 `data.item_list` 的视频 instruction 内有 JSON 字符串 `template`，继续解析 `selector_list[].template`，读取 `key=video-model/video-duration/video-ratio` 的 `option_list`。
2. `POST /samantha/skill/pack`，HTTP 200。当前响应仅列 Fast/1.0，未列 2.5。它仍含六比例和 5/10 秒，但不能作为完整模型目录。

action bar 与两个模型菜单均显示六档比例。当前原生时长选项为 5/10 秒，尚未出现 15/30。2.5 配置中的“5 倍消耗”只是标签；不能据此推断真实扣量。

结论：解锁参考项目的静态 `skill/pack` 替换不能直接当生产目录。最终方案需要解析实际 action bar、按账号/模型记录能力，并用真实生成结果验证，不覆盖成参考仓库的旧模型表。

### 3.3 真实请求功能载荷

```json
{
  "chat_ability": {
    "ability_type": 17,
    "ability_param": "{\"ratio\":\"16:9\",\"model\":\"seedance_v2.5\",\"duration\":5,\"camera_movement\":\"fixed\",\"input_box_content\":{\"user_input_content\":\"<本轮测试提示词>\",\"reply_message_format\":\"生成视频：%s\"}}"
  }
}
```

完整请求还包括 `client_meta`、`messages[].local_message_id`、`content_block`、`option.unique_key` 等。原生文字块是 `block_type=10000`；A账号两条基线无图片，B账号的一图请求另有 `block_type=10052` 附件块，见3.5。`ability_param` 是 JSON 字符串，不是嵌套对象。

Fast 的同一字段实际为 `{"ratio":"9:16","model":"seedance_v2.0","duration":10,...}`。这已证明网页选择的 10 秒确实传入请求，不能再把下述 5 秒回复解释为前端没传值。

`camera_movement=fixed` 是本次原生请求值，不代表已验证所有镜头参数，也不应未经对照实验扩展新 UI。

### 3.4 查询协议与消息语义

本轮实际使用 `POST /im/chain/single`：

```json
{
  "cmd": 3100,
  "uplink_body": {
    "pull_singe_chain_uplink_body": {
      "conversation_id": "<SSE_ACK 取得的原会话>",
      "anchor_index": 9007199254740991,
      "conversation_type": 3,
      "direction": 1,
      "limit": 20,
      "ext": {},
      "filter": {"index_list": []},
      "evaluate_ab_params": "",
      "evaluate_common_params": ""
    }
  },
  "sequence_id": "<当前查询序列>",
  "channel": 2,
  "version": "1"
}
```

`pull_singe_chain_*` 中 `singe` 是实测协议原拼写，不能自行改成 `single`。上例 `limit=20` 来自网页样本，最终应按真实分页响应实现，而非用固定轮询次数判任务失败。

响应路径为 `downlink_body.pull_singe_chain_downlink_body.messages`；需检查 HTTP 和 `status_code`，并处理 `has_more`。消息同时可能含数组 `content_block` 和序列化 JSON `content`。本轮先获得 `SSE_ACK` 的聊天会话关联，随后在该会话的新消息中取得 `block_type=2074` → `content.creation_block.creations[]` → `type=2` → `video`。成功样本video.status为3，含download_url、duration、width/height、video_model。不要只盯着原助手消息：完成结果是后续异步消息。独立任务取消/状态枚举全集仍未知。

### 3.5 单张参考图片的真实上传与附件结构

此前自动化文件选择器即使开启扩展文件权限仍返回Not allowed；已改用原生文件选择器成功上传自写无隐私PNG。当前上传不再被工具权限阻塞。fixture为 `reference-boat.png`，960×540，哈希见 `evidence/live/reference-fixtures.json`。

已捕获链路：

1. `POST /alice/resource/prepare_upload`，body `{"tenant_id":"5","scene_id":"4","resource_type":2}`，返回 service_id、upload_host、upload_path_prefix 及临时 upload_auth_token；不保留凭据值。
2. `GET https://imagex-ap-southeast-1.bytevcloudapi.com/`，query `Action=ApplyImageUpload`；响应 UploadAddress 包含 StoreInfos、UploadHosts、SessionKey。观察到二进制目标主机 `tos-myb1-share.vodupload.com`；后续追回早前二进制请求，实际为POST、HTTP200，Content-CRC32八位十六进制与PNG一致；不是参考中猜测的PUT，详见09。
3. 同一imagex主机 `POST`、`Action=CommitImageUpload`，成功返回 Results[].Uri、PluginResult 中960×540/png规格；**该Uri与后续发送图片image.uri相同**。
4. `POST /alice/message/pre_handle_v2_without_conv`，上传实体包含 image.key、identifier，返回code=0与pre_generate_id。
5. `/chat/completion` 的 messages[].content_block 中，图片附件在10052块，文字在10000块；10052实际路径为：

```json
{
  "block_type": 10052,
  "content": {
    "attachment_block": {
      "attachments": [{
        "type": "<本轮实际整数见脱敏JSON>",
        "identifier": "<ATTACHMENT_ID>",
        "image": {
          "name": "reference-boat.png",
          "uri": "<COMMIT_IMAGE_URI>",
          "image_ori": {"url":"<PRIVATE_IMAGE_URL>","width":960,"height":540,"format":"png","url_formats":{}}
        },
        "parse_state": "<实际整数>",
        "review_state": "<实际整数>",
        "upload_status": "<实际整数>",
        "progress": "<实际整数>",
        "src": "<BROWSER_LOCAL_SOURCE>"
      }]
    }
  }
}
```

以上是脱敏结构说明，枚举不猜含义，精确值见B样本JSON。后端编译使用已提交资源信息，不能使用浏览器blob URL替代服务器图片资源。该15秒请求仅证明上传和附带提交；其成片被额度阻塞。随后Fast5秒/16:9普通单图已实际成片，参考形状、配色与构图保留，见09。双图顺序、图片mention语法、首帧/尾帧角色仍无成功证据。

## 5. 需要修正的实现假设

1. **模型 ID**：2.5 不走参考项目固定 2.0 的 normalizer。Fast 与 2.5 分别建 profile。
2. **能力目录**：读取实测 action bar；旧 skill pack 只作已知辅助来源，不合并出未验证能力。
3. **成功判定**：HTTP 200、SSE_REPLY_END、助手承诺、聊天 `is_finish` 均不是媒体成功；只有可信视频任务/媒体证据才能推进状态。
4. **额度**：助手说“剩余0”不得直接把账号标为 quota_exhausted、触发换号或写账。保存为未核实提示，精确余额仍 UNKNOWN。
5. **参数生效**：Fast实际10.08秒，验证了10秒请求，否定了5秒文案。必须记录请求与媒体规格，不能由自然语言回复覆盖模型、时长或余额。
6. **15/30秒**：15秒先被A账号日次数上限阻塞，后被B账号具体12/4额度提示阻塞；30秒未发。原生配置没有提供，扩展改菜单和载荷都不等于真实15/30秒成片。
7. **反代可用性**：本轮使用原生网页；尚未把导入会话放到服务器隔离环境重放。不能把浏览器点击成功当 API 反代通过。
