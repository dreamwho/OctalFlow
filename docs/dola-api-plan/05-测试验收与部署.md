## 1. 验证层次

| 层次 | 证明什么 | 不能证明什么 |
| --- | --- | --- |

| 部署环境验证 | 镜像/运行依赖/数据库/存储/网络实际可用 | 其他未测平台、持续可靠性 |

报告必须分别列出这些结果。本轮已执行测试见 01 和 evidence，不是此完整矩阵已经通过。

## 2. 默认测试环境

默认隔离数据目录、固定假凭据、随机空闲 TCP 端口、本地协议与支付 fixture；禁止读取管理员当前真实渠道作为自动化默认上游。真实 Dola 单独显式启用、单独记录。

测试不得绑定用户已有浏览器/服务器端口后误认为应用响应。Playwright `reuseExistingServer:false`；开跑前确认每个 Web/协议/支付/Dola fixture 端口空闲；占用则明确失败并选择新端口。

新 Dola fixture 至少提供：账号校验/余额、上传、dispatch、SSE、query、媒体读取、callback/事件回放，以及每条请求计数器和“创建请求已收到但连接中断”模式。所有测试通过读取计数断言没有二次创建。

真实样本脱敏成结构 fixture，不把浏览器 Profile/HAR/token 粘进测试。HTTP 日志仅假 token；异常测试刻意包含假敏感字段以断言脱敏路径。

## 5. 去水印质量与性能验收

URL方案的已完成两样本证据见07，应用交互尚未测试。URL方法优先检查来源关联、签名刷新、流式下载、帧数/时长、真实音轨、完整解码和水印；下述修复区域误差、轨迹与CPU指标只适用于另行启用的本地修复方法。

保存自有真实 Dola 原片和派生片的关联摘要，原文件SHA-256保持不变；正式共享证据不使用未授权第三方视频。

逐项检查：全片水印所有出现区间、弹出/消失边缘、移动轨迹、浅色/暗色背景、人物面部和手部、商品边缘、画面内字幕/Logo、复杂纹理、镜头切换、横竖屏与不同分辨率。

视频与原片同尺寸/方向，时长及帧时序合理，无新增黑边/裁切；音轨保留且尾部同步。空检测与修复质量不足分别报告，不能只由工具exit code代表质量。

用合成“带水印/已知干净背景”样本量化修复区域误差和非修复区域变化；用真实样本人工查看全片和重点帧。质量阈值经样本基线确定，不能引入“100%去净”保证。

性能记录环境CPU/RAM、视频规格、时长、处理墙钟时间、峰值RSS、临时磁盘峰值和并发量。对比原脚本整片缓存与两遍流式策略；资源配置据此给管理员建议，不能未经测量承诺30秒视频秒级处理。

`pnpm start` 是持续服务，实际由受控终端/supervisor 管理。重启前只终止本次已确认的项目进程，保留用户其他服务。使用普通常驻应用回归时设置其独立端口；Playwright自带webServer会另起隔离生产实例，不能占用同一端口。

```bash
# 已注册Dola项目/测试后，先检查收集，再跑生产模式浏览器回归
pnpm -C web exec playwright test --list
pnpm -C web e2e
```

当前 `e2e` 的 prehook 会清理 `.e2e-data/.e2e-artifacts/playwright-report`，保存需要保留的上次证据后再运行；不要让这个目录指向真实业务数据。Dola专用配置若新增，命令使用 `--config playwright.dola.config.ts`，同时满足空闲端口、production start、隔离凭据和完整矩阵。

已有 `pnpm -C web check:release` 会重复执行全量lint/format/test/typecheck/build及审计，可作为统一门禁入口；共享真实PostgreSQL测试库时必须保证其内置vitest也禁用文件并行（先改适用调用或用经审查的等价串行门禁）。不要先跑全套再无依据重复全套。记录现有工作区引起的基线失败与Dola新增失败，未经授权不修无关文件。

本轮已进入应用实施并完成生产构建与本地生产启动冒烟；真实 Dola Provider、目标 Linux 和最终媒体仍按本清单分层验收，不能用本地构建代替上游成片证据。

## 8. 本地运行与部署拓扑

### 8.1 本地生产监督启动

参照`geminiai-local-runtime.mjs`新增Dola本地运行管理：显式URL+KEY优先；未配置远程服务且启用本地Dola时启动已安装的锁定Camoufox环境；独立空闲端口；生产start退出时回收本次创建的子进程和私有临时profile，不能杀用户Chrome或读取用户日常浏览器Profile。

Provider依赖、浏览器二进制与水印运行库在安装/构建阶段就绪，不在用户点击生成时临时下载安装。浏览器不可用应使Dola readiness失败并可诊断，不让整个网站白屏。

当前 Provider 运行配置：

| 配置 | 用途 |
| --- | --- |
| `DREAMYO_DOLA_PROVIDER_URL` | Web → Dola Camoufox Provider 的受控私网地址 |
| `DREAMYO_DOLA_PROVIDER_KEY` | Web → Provider 的独立随机服务密钥 |
| `DOLA_PROVIDER_KEY` | Provider 校验 Web 内部请求的对应密钥 |
| `DOLA_ENABLE_BROWSER=1` | 显式允许 Provider 启动 Camoufox 页面会话 |
| `DOLA_WEB_URL` | Provider 打开的 Dola Web 地址，通常使用登录入口 |
| `DOLA_TASK_STATE_PATH` / `DOLA_TASK_ENCRYPTION_KEY` | Provider 任务状态和 Cookie/代理快照的加密持久化；不存明文永久账号库 |
| 通用代理管理绑定 | 保存 `node:<id>` 或 `group:<id>` 引用；每个任务解析同一出口快照，不增加台湾专用配置 |

管理员业务配置（并发、轮询策略、自动去水印、算法选项）进入数据库，不能只放环境变量导致页面保存不生效。密钥从服务端配置读取，不注入NEXT_PUBLIC变量。

### 8.2 Docker/服务器

应用/Worker同一构建版本；Dola Provider私网服务、不对公网publish；URL去水印沿用现有持久Worker；只有另行启用本地修复方法才部署独立CPU进程或服务，资源由部署配置控制。容器用户非root，临时目录最小权限；正常TLS校验，不关闭证书检查。

持久项：现有PostgreSQL或JSON数据目录、媒体存储、加密配置密钥及必要安全配置。账号授权状态由Next加密保存；临时浏览器文件若必须落盘，目录0700/文件0600、受控生命周期，不能作为备份中的明文Cookie库。

检查默认、本地、低内存、外部数据库、宝塔、离线和离线外部数据库共七套应用Compose。每套明确“默认启用/可选profile/不适用”的策略，不要求全部无条件启动浏览器服务；涉及的结构契约测试一起更新。宝塔host网络只写其专用配置，公共业务不硬编码宝塔地址。

离线镜像包含浏览器/字体/必要系统依赖与媒体探测工具；OpenCV和修复编码运行库只随可选本地修复镜像提供；对目标CPU/libc执行真实import、浏览器启动及编码测试。镜像构建成功不代表目标服务器可运行。

反向代理允许SSE/NDJSON流式，关闭对应缓冲；Route maxDuration、内部请求timeout、Undici headers/body timeout与配置最长模型窗口一致，并预留落盘时间。查询是持久异步任务，不能用无限HTTP等待代替Worker。

### 8.3 健康、观测与恢复

健康分别为进程live、依赖ready、账号状态、业务成功率；网关首页绿色不能代表账号有额度。记录请求ID、账号安全标签、阶段耗时、失败类别、浏览器会话数量、队列长度、后处理CPU/RSS和临时文件回收。

恢复演练：数据库+加密密钥+媒体恢复后，账号仍可解密；未完成任务用保存的ID恢复；媒体签名过期可重新取；密钥丢失时明确需重授权而不是假成功。普通业务导出不携带账号凭据。

## 9. 上线开关、回滚与上传包

初始状态：Dola外部网关关闭，自动去水印关闭；服务准备完成后由管理员导入账号、启用所需模型及账号，验证后逐步开放。不要自动改全站默认文本/图片/视频模型。

关闭新任务：先停用Dola渠道/网关的新创建入口，已受理任务保留查询和媒体领取。需要回滚时停发新任务、保留数据库和安全凭据、等待/转入待核对的存量任务，再部署之前确认可用的应用/服务版本。回滚不得删除账号、任务、原视频或派生媒体；数据库新表可保留，不写清理旧表兜底。

部署包文件夹使用 `本次修改需上传文件_YYYYMMDD`（准备当天）；准备时先定位并删除旧的同用途上传文件夹，再重建，保持项目目录结构。路径检查仅作用于这个发布目录，不误删本轮方案、参考项目、用户现有构建或未提交文件。

包中必须包括本次实际变更的应用/服务源码、锁文件、配置示例、相关数据库定义和启动所需构建闭包。Next.js交付按当前Standalone模式准备完整`.next/static`/public/运行依赖，不能拿几个React源码或不完整hashed chunks声称服务器可覆盖运行；如另做静态包，追踪入口和递归资源依赖，只含本次可达资源。

排除：真实env、账号Cookie/状态、数据库文件、原始HAR、签名URL、未脱敏日志、临时媒体、测试生成视频、无关历史构建和参考ZIP。提供manifest（相对路径、大小、SHA-256）及严格UTF-8检查结果，检查常见乱码标记。

本轮已有应用与 Provider 实现修改；未把本地启动冒烟当作生产部署。若需要服务器上传，按本节规则重新生成当天的 `本次修改需上传文件_YYYYMMDD`，只放本轮实际变更文件，并附 manifest、哈希和 UTF-8 检查结果。实施完成报告按用户要求列“文件路径 + 一句话说明”，并分别列：自动化通过、真实Dola通过、浏览器通过、未完成项、生产部署是否实际执行。
