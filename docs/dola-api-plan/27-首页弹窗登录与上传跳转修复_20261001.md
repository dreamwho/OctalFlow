## DOLA 上传准备

报错路径中的 `_prepare_upload()` 原本使用 `Page.evaluate` 等待页面里的异步 fetch 响应；页面文档替换会销毁该 Promise 所属的执行上下文。修复在主页面脚本环境启动原有 prepare 请求，捕获浏览器 SDK 加签后的完整请求并中止原始传输，再由同一个浏览器上下文的 APIRequestContext 实际发送一次。响应读取不再依赖旧文档中的 JavaScript 执行上下文。

签名、请求体、请求头、Cookie 与提交代理保持浏览器生成的实际内容；使用既有上传传输的 90 秒超时。没有新增固定等待、重复生成请求或直接出口兜底。ImageX Apply、二进制上传、Commit 仍遵循独立上传出口配置。

真实 Camoufox + 随机端口本地 TCP 回归连续执行三次准备请求，每次都在服务端收到请求且尚未返回时导航到新文档，再释放响应。三次均返回有效配置，原始 SDK 路径产生的签名和请求头、Cookie、请求体保持一致；每次源站只收到一次 POST。API 请求经认证计量代理传输，独立源站收到的请求字节与计量上行增量完全一致。该测试是文档替换故障回归，不是实际 DOLA 生成成功证明。
