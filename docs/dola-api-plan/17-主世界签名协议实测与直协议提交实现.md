# 主世界签名协议实测与直协议提交实现

日期：2026-09-17。状态：**Dola 视频与图片的协议级提交已在应用内实现并通过真实上游端到端验证；提交通过页面主世界签名 XHR 完成，结果查询、会话与媒体读取全部为直协议 httpx。** 本页记录本轮协议证据、被否决的路线和最终实现合同。

## 1. 问题与结论

用户要求：Dola API 的 HTTP 协议提交不要依赖手工页面自动化，应实现协议级提交，并覆盖视频与图片。此前全部提交失败（`submission_unknown`），本轮定位为 `/chat/completion` 的 `a_bogus` 动态签名缺失。

已证明：

- 未签名创建请求（图片与视频相同）返回 `STREAM_ERROR 710022004`，decision 为 `type=verify / subtype=slide / from=shark_admin`。
- 携带无效签名的请求返回 `710022002 当前服务访问频繁`（无 decision）；两者都不是真实频控，签名校验失败的不同表现。
- `window.byted_acrawler / bytedAcrawler / __acrawler / ABogus` 四个全局签名器在当前页面全部为 undefined；页面自身请求的 `a_bogus` 由 `bdms-sdk` chunk（`static/js/async/bdms-sdk.f36aabd9.js`）内部的 JSVMP 生成，仅存在于主世界，且对环境指纹敏感。
- 页面脚本（含 `s2-chat-runtime`）在 `window.bdms.frontierSign` 存在时跳过 acrawler 加载，即 bdms 是唯一 HTTP 签名来源。

## 2. 被否决的路线

| 路线 | 结果 | 证据 |
| --- | --- | --- |
| 纯 httpx 无签名提交 | verify/slide 拦截 | 图片与视频各一次直测 |
| 借用页面真实 a_bogus 重放（换 body） | 710022002 | 重放实验 |
| 移植 toutiao 版 bdms JSVMP（HZhertz 补环境）在 Node 生成 a_bogus | 710022002（页面内与 httpx 均拒） | `tt_sign.js` 产出 160 字符值，页面真实值约 168 字符；版本不匹配 |
| dola 版 bdms-sdk chunk 在 jsdom 补环境执行并 patch XHR | 钩子安装成功但不签名（指纹校验不通过即静默跳过） | `run_dola_bdms.js`、`test_bdms_init2.js` |
| Playwright/Camoufox 隔离世界 hook fetch/XHR | 永远观察不到页面主世界请求 | add_init_script 世界隔离 |
| Web Worker / Service Worker / WASM / iframe 签名 | 全部不存在 | 逐项排查 |

结论：当前无浏览器纯直协议签名没有可复现路径；可行解是让**页面主世界自己发出我们构造的协议请求**。

## 3. 采用的提交合同

```text
Python Provider（协议构造方）
  → Camoufox 页面（Cookie 账号 + 可选通用代理出口）
  → add_script_tag 注入主世界脚本（绕过世界隔离）
  → 包装当前（已被 bdms patch 的）XMLHttpRequest.prototype.open 记录最终 URL
  → 循环 open 直到最终 URL 含 a_bogus 才 send；超时未签名则失败 signing_hook_unavailable
  → SSE 响应写入隐藏 textarea，隔离世界控制器轮询读取
  → conversation_id 落库，任务进入 accepted
Next.js / 直协议 httpx
  → /im/conversation/info + /im/chain/single 双端点累积查询（无签名）
  → 按任务能力提取：视频取 creations[].video.download_url；图片取 creations[].image.image_ori/image_raw.url
  → completed 持久化 videoUrl / imageUrls
```

关键实测修正：

1. **签名两阶段激活**：bdms patch open 早于签名生效；仅检查 open 是否被 patch 会发出未签名请求。必须在底层包装中确认本次 open 的最终 URL 已含 `a_bogus` 再发送，否则丢弃重试。
2. **结果按能力门控**：视频会话同时包含封面缩略图（image 结果）；视频任务只认 `download_url`，图片任务只认 image URL，否则封面图会误判视频完成。
3. **查询双端点累积**：`/im/conversation/info` 可能只返回封面，视频在 `/im/chain/single`；任一端点先到图片就提前返回会漏掉视频。
4. **Firefox 代理凭据**：Camoufox 不接受 URL 内嵌用户名密码，须拆分为 `server/username/password`。
5. **页面指纹**：不得叠加 Chromium UA 伪装（旧 BROWSER_INIT_SCRIPT + sec-ch-ua）；Camoufox 原生 Firefox 指纹可直接通过。
6. **验证 decision 检测**：decision 是 `extra.decision` 内的 JSON 字符串，正则必须容忍转义引号；`710022002` 与 `710022004` 都按服务频控/签名失败归类。

## 4. 图片协议合同（本轮新实证）

- 模型：`Seedream 4.5`（页面 wire 名）；`ability_type: 3`，`ability_param` 为双层嵌套：`{"ability_param":{"model":"Seedream 4.5","input_box_content":{"user_input_content":"…","reply_message_format":"生成图片：%s"}},"ability_type":1}`。
- 比例通过提示词文本传递（`…，比例：1:1`），无结构化 ratio 字段；Provider 接受 `ratio` 或 OpenAI 风格 `size`（自动映射最近比例）。
- 结果：`block_type 2074` → `creations[].image.image_ori/image_raw.url`；`image_ori` 通常为无水印原图（`image-qvalue` 模板），带 `_wm_` 的为水印版，提取时原图优先、全部保留。
- 参考：视频协议沿用 `ability_type: 17` + `{ratio, model, duration, camera_movement, input_box_content}`，此前文档已覆盖。

## 6. 应用实现落点

- `services/dola-api/src/dola_api/page_scripts.py`：新增 `MAIN_WORLD_SUBMIT_SCRIPT`（主世界签名发送 + DOM 回传 + 未签名重试）。
- `services/dola-api/src/dola_api/session.py`：协议请求构造（`_build_request_body`/`_build_completion_query`）、`_execute_completion_submit` 主世界执行、能力门控完成判定、双端点刷新、代理凭据拆分、原生 Firefox 指纹。
- `services/dola-api/src/dola_api/protocol.py` / `contracts.py` / `app.py`：`dola-seedream-4-5` 图片模型、`imageUrls` 字段、`/v1/images` 创建与查询路由。
- `services/dola-api/src/dola_api/query.py`：`extract_image_urls`（原图优先）、`fetch_generation_result` 双端点累积。
- `web/src/lib/server/dola/types.ts` / `provider.ts` / `service.ts`：图片模型档案、`/v1/images` 路径与图片参数校验、后台测试窗口支持图片模型。
- `web/src/lib/channel-protocol-registry.ts`：Dola 渠道 `capabilities: ["video","image"]`，图片操作 `createPath /images`、`queryPath /images/:task_id`、内置模型 `dola-seedream-4-5`。

- `web/src/app/api/image-tasks/image-task-support.ts`：`accepted` 计入进行中状态；`needs_review` 转人工确认而不是终态失败。

## 7. 边界与后续

- 15/30 秒时长：协议直发 `duration` 已支持（2.5 档位 5/10/15/30），无需 30s-unlocker 的页面配置改写；真实 15/30 秒成片仍需按 11 的矩阵验收。
- 图片参考图（图生图）：上传链路复用，但图片带参考的 `ability_param` 结构未实测，本期注册为不支持参考图。
- 去水印：图片提取已优先 `image_ori` 无水印原图；视频自动去水印沿用 07 的 URL 提取（`vodPayload` 通道保留）。
- 目标 Linux 部署、滑块真实挑战恢复（`verification` 流程保留并已切换到主世界提交）与多账号并发仍待验收。

## 9. 请求日志任务生命周期（2026-09-17 追加）

对齐 GeminiAIStudio 的过程日志模型，修复"只要有响应内容就设为成功"：

- 阶段机：日志新增 `submitted`（已提交/排队中）与 `generating`（生成中）任务阶段；`success/failed/needs_review` 语义改为任务终态（生成完成/生成失败/待人工确认）。`dolaTaskLogPhase(status, verification)` 统一映射 Provider 状态 queued→submitted、accepted/running→generating、completed→success。
- 单任务单日志：创建 POST 落一条日志并在上游受理后停留 `submitted`；后续 GET 轮询按 `task_id + source` 反查原创建日志（优先 POST 行，Postgres 端新增 `dola_request_logs_task_idx`）调用 `advanceDolaTaskLog` 推进，不再每次轮询新开一条"成功"记录。生命周期条目只在阶段跃迁时追加，避免轮询刷屏；终态把 `durationMs` 收敛为"提交到完成"整段耗时。
- 最终响应内容：完成/失败时响应摘要保留 `videoUrl/imageUrls/data[].url` 明文（Cookie/Token/base64/dataurl 仍脱敏），时序末条 detail 附结果地址列表。
- 覆盖面：站内运行时 `/api/ai/system/:channel/v1/*`、外部网关 `/api/dola/v1/*`、后台实测 testDolaVideo/queryDolaTask 三个入口统一；轮询对原日志 404 时收敛为"任务在 Provider 中已丢失"，5xx 瞬时错误不改判任务失败（符合"不得因本地执行器异常判失败"约束）。
- 实测：真实图片任务日志时序 排队中(+0ms)→代理路由(+75ms)→上游请求(+115ms)→已提交(+115ms)→生成中(+11.2s)→生成完成(+33.4s，5 张结果地址)，后台详情抽屉时间线与响应摘要渲染正常；回归 `log-store.test.ts` 3 项新增用例（阶段映射、单任务推进、失败收敛与 pending 统计）。
