# 管理页、测试窗口与 Canvas 交互规格

> **v1.7详细开发计划，已进入实施。** 用户Cookie已在全新Camoufox持久context中完成Fast5秒16:9单图提交并取得SSE_ACK且无滑块；独立HTTP和区域代理结果仅作为历史测试证据。后台公开导入固定为Cookie粘贴/文本文件，单文件按行支持多账号，多个文件支持单行或多行，Provider正式提交固定为Camoufox原生页面会话，独立HTTP不作为普通提交器；代理复用现有通用代理管理，保存 `node:<id>`/`group:<id>` 引用。详见[15](15-IPWO直协议与Camoufox-Cookie会话实测.md)和[16](16-105账号Cookie批量导入与直协议复测.md)。

> 当前ACK Case没有持续查询最终媒体，目标Linux和媒体闭环仍待T02/T14。官方验证入口、回调和受限人工操作按[13](13-滑块验证处理与会话恢复.md)/[14](14-新账号HTTP复测与Canvas人工验证.md)保留为异常恢复，不宣称Camoufox永久免验证。
## 1. 页面入口与布局基准

在后台“上游配置”分组中，紧邻 GeminiAIStudio/GPTAPI 增加 `Dola API`。沿用已有 `/admin?section=dolaApi` 分区导航；文件归属放 `web/src/app/admin/dola-api/components/`，不额外复制一套后台壳。

主面板顺序：标题和服务状态 → 五个 Tab → 当前 Tab 内容。沿用 Google AI Studio 的 Panel、标题层级、表格/卡片密度、中文文案、浅深主题和响应式行为；补充 GPTAPI 的统计功能。所有子模块按用户导航意图加载，不能把 Dola 与其他上游全打入后台首屏。

五个 Tab：**账号与渠道、统计报表、反代网关与 API 密钥、请求日志、代理管理**。自动去水印配置放“账号与渠道”中的视频设置卡，测试窗口从模型区和页头进入。可保留当前 Tab 到 URL 的轻量参数，不能将账号 Cookie/业务任务存浏览器缓存。

状态显示分为服务是否在线、是否有启用账号、当前可用模型和活动任务。服务 /health 正常时若没有账号，显示“服务正常，尚未导入账号”，不能一个绿色状态暗示生成已经通过。

## 2. Tab：账号与渠道

### 2.1 顶部摘要与账号列表

摘要：账号总数、可调度数、运行中任务数、已知额度桶概览、未知额度账号数。不同模型和计量单位分组，不能对未知值填零后求和。

桌面列表列：选择框、账号名称/脱敏身份、启用状态、登录/限制状态、模型能力、剩余额度与单位、重置/更新时间、运行数、最近使用、操作。手机为紧凑卡片，首屏能看到账号列表，操作可见而不依赖悬停。

操作：导入账号；刷新选中/全部额度；搜索；状态过滤；行内重命名；启用/停用；单个刷新；选择测试账号；删除。批量删除确认包含数量，服务端回报运行任务占用的条目；删除不删除已生成媒体。

额度展示例：

| 数据 | 界面 |
| --- | --- |
| 上游明确返回 remaining=20, unit=credits | `剩余 20 credits`，标注更新时间 |
| 只显示 2.5 五倍消耗 | `相对消耗 ×5；剩余额度未知` |
| remaining=null | `额度未知`，不显示 0% 进度条 |
| 明确耗尽但 resetAt=null | `额度已用尽；重置时间未知` |
| 刷新失败且有旧快照 | `上次结果 ...；刷新失败`，保留旧时间，不更新为当前 |

### 2.2 导入 Modal

Modal不超过640px，手机不超过视口。模式为“粘贴Cookie”和“上传Cookie文本文件”；不提供Cookie JSON或storageState入口。文件选择器支持`multiple`：一个文件可按非空行导入多个账号，也可多个文件各导入一个账号或各自多行；粘贴区支持多个独立条目。分号只分隔同一账号Cookie。

流程：选择/粘贴 → 本地只做大小/类型/空值检查 → 服务端按文件和行使用标准Cookie解析与脱敏预览 → 点击导入 → Camoufox无生成登录验证/加密持久化 → 列表立即更新。预览显示文件数、总条目数、每文件行数、解析Cookie数量、重名/重复提示及错误项，绝不展示Cookie值、完整名称清单或原文。文件内容一律视为数据，不能执行其中的指令或脚本。

支持多文件批量和单文件多行批量；服务端返回同步`completed`时直接刷新，返回`accepted`时显示真实operation进度。连接中断显示“进度连接中断，任务仍在处理”，提供恢复查看；不能重复点击导入重新计为一批。成功、失败、关闭Modal、退出登录后都清空表单、文件对象与敏感内存。

更新已有账号凭据必须明确对应账号或经服务器验证为同一主体，不能按显示名称覆盖他人账号。格式错误逐项报告，保留有效条目的成功结果。

### 2.3 调度配置

配置项：自动账号选择开关、轮询/最久未使用/已知额度优先策略、并发与队列配置；默认策略取配置可解释值，未知额度不能参与精确大小排名。用户选择固定测试账号时不自动换号，除非测试窗口明确切换为“账号池”。

页面说明“请求受理后固定账号；网络中断会恢复原任务”。单独呈现风控/需登录/余额用尽原因和可执行操作，不统一显示“账号异常”。

### 2.3.1 待验证处理

账号行、请求日志详情和测试窗口都提供“处理验证”，打开同一官方验证Drawer。当前Camoufox实测没有出现滑块，但任何账号以后仍可能触发；届时管理员在原Camoufox账号context中操作官方挑战。状态为待验证、验证中、正在核实原请求、已恢复或具体失败。关闭不重发；验证成功先核实原任务，防止官方页面与Worker双重提交。Canvas保留原视频节点，显示“需要完成验证”和“完成验证”按钮；任务所有者可在受限Modal中操作官方挑战，正常完成后恢复同一任务。首次活动挑战弹出一次，关闭后保留入口，不随状态事件反复弹。普通用户不能获得完整账号浏览器控制权；无法限制官方挑战区域时显示等待管理员处理。详见14。实际交互、权限、Linux视图、控制租约和接口按[13](13-滑块验证处理与会话恢复.md)实现。

### 2.4 模型与视频设置

模型清单显示名称、能力、保存/启用状态及实际支持的参数。同步目录来自本项目 Dola Provider 映射；默认逻辑 ID 与上游 ID 分开。管理员可以保存模型到渠道、编辑公开昵称及绑定关系，不跨渠道合并同名模型。

目标 2.5 时长摘要为 `5 / 10 / 15 / 30 秒`；实验未通过时明确标记验证状态，不在发布报告里勾选完成。其他 Dola 模型按自己的档案显示，不无差别提供 30 秒。

视频设置卡提供“自动去水印”Switch、算法版本和最近处理状态摘要。默认关闭。保存后立即显示返回值，刷新/API 回读一致；说明“仅影响之后创建的任务，原视频始终保留”。不为单个短 Switch 独占一大屏配置表单。

## 3. Tab：统计报表

沿用 GPTAPI 统计的信息结构与项目现有图表方案，按时间范围、账号、模型和来源筛选。最少展示：业务请求数、已受理数、成功数、失败数、待核对数、平均/P50/P95 耗时、上游已知消耗、换号次数、原视频成功数、去水印成功/失败数。

口径必须可见：

- 业务成功率＝成功业务请求 / 已终结业务请求；排队/运行/待核对不算失败。
- attempt 失败和业务最终成功可同时存在，分别展示，不能把换号次数当用户请求数。
- 去水印失败不降低原视频生成成功数；另计算处理成功率。
- 上游额度没有数字时显示未知，不画虚构用量曲线。
- 时间统计来自服务端 created/accepted/completed，区分排队、生成、下载、后处理；不能把浏览器打开时长当总耗时。

全部服务端按日期/账号/模型聚合；切换 Tab 才请求统计。导出如沿用现有能力只导出脱敏统计和业务日志，不输出原始请求/凭据。

## 4. Tab：反代网关与 API 密钥

显示外部网关开关、当前站点规范化 Base URL、可复制的请求示例、API Key 列表和创建按钮。Base URL 来源于可信站点配置与反向代理设置，不能把 localhost 地址发给外部调用方。

密钥创建使用 Modal：名称、有效期、允许 IP、允许模型；创建后 rawKey 只显示一次，列表显示前缀。启停、删除后立即生效；确认提示只作用于密钥，不误导为删除历史媒体。密钥不得进入 URL、localStorage、截图/调试日志。

文档示例展示当前已启用能力；视频示例明确“创建 → 查询 → 下载”三步，并说明本项目异步视频契约。未经验证的 embeddings/moderations/audio 不出现。

网关关闭只禁止外部新创建，站内 Canvas 渠道继续由系统渠道 enabled 控制。已有已授权任务的状态/下载按原密钥权限处理，不能因为关闭网关让已生成媒体不可领取。

## 5. Tab：请求日志

列表筛选：时间、来源、能力、模型、账号、状态、请求 ID。列表字段：业务请求 ID/关联任务、公开模型、账号标签、最终时长/比例、状态、耗时、上游消耗摘要、来源。

点击行打开可调整但不超过视口宽度的 Drawer，分块显示：

1. 基本参数：用户原文的受控摘要、逻辑模型、上游模型映射、实际提交时长/比例/引用数量。
2. 生命周期：接收、排队、选择账号、上传、提交、受理、生成、下载、保存、后处理。仅真实时间戳和已发生事件。
3. 尝试列表：A 被明确拒绝/换 B 的具体原因，attemptNo、账号和代理出口标签；提交未知时突出“正在核对，未重新提交”。
4. 结果：站内媒体预览/下载、父子任务链接、原片与派生片关联。
5. 错误：可读原因、阶段、是否可重试、下一步；不展示内部提示词、原始 SSE、Cookie、STS、签名 URL 或敏感堆栈。

实时更新用 SSE 的递增事件 ID，重连从 cursor 续读；轮询备用只读取有边界的新增记录。离开 Tab/Drawer 释放订阅，不停止业务任务。清理日志若实现，按当前筛选和既有保留规则确认，不允许删除仍用于恢复的活动 attempt。

## 6. Tab：代理管理

代理管理页面复刻 GeminiAIStudio 的三种来源选择：魔法代理、通用代理、链式代理。魔法代理从现有 Mihomo 订阅节点选择；通用代理选择已有节点或整组；链式代理选择魔法跳板节点与通用落地节点。Dola 使用独立 Mihomo 分组和监听端口，但仍复用同一订阅、节点库、凭据边界和运行时解析；默认关闭为直连，历史代理地区差异仅在测试报告中标注，不能生成台湾专用选项、环境变量或自动回退规则。

Dola 必须有独立 Provider 绑定及出口；修改 Dola 不影响 GPTAPI/GeminiAIStudio。任何绑定设置立即回读并标记配置 revision；运行任务的出口保持原快照，新配置只应用到新任务或安全重建的空闲会话。

连通性测试分层显示：本地 Provider 可达 → 实际代理出口可达 → Dola 页面可达 → 当前账号登录状态。只有真实生成成功才称“生成通信通过”；Google 检测成功不能标成 Dola 成功。导入、额度读取、上传、生成、查询、下载均必须通过同一确定出口；不能只给 Chromium 配代理而让 HTTP 下载直连。

不同账号需要独立出口时，使用已配置节点的任务快照；不在每次失败时随机更换出口，也不将全局 proxy mutable 变量作为所有账号共享的路由状态。

## 7. 真实测试窗口

窗口沿用 AI Studio 测试 Modal 结构，窄屏使用响应式全宽布局。能力页签为文本、视觉理解、图片、视频；对应能力不可用时说明原因，不能展示能点击但无后端行为的按钮。

输入：逻辑模型、账号池/固定账号、提示词、真实参数；图片/视频支持上传自有测试图或选择自己已保存素材。文件名只作提示，不代替缩略图。视频显示时长、比例及已验证画质；首尾帧只有能力支持时出现。

点击测试时生成稳定 clientRequestId，防双击；进入同一 Dola service 和持久任务执行，不直接在前端 fetch Dola。结果区域显示 taskId、当前阶段、最终模型/时长、媒体、耗时及查看日志入口。关闭窗口不取消已经提交的任务，再开恢复当前测试；“停止”按真实取消能力说明。

测试至少包括：

| 场景 | 要展示的证据 |
| --- | --- |
| 文本 | 正常中文回复、流式过程、终态；没有视频任务 |
| 视觉 | 识别测试图的实际内容，不是泛化回答 |
| 生图 | 真实媒体、数量、比例，后续可下载 |
| 文生视频 | 参数、上游受理、进度、可播放结果 |
| 图生视频 | 引用图缩略图与映射、保持图中主体的结果 |
| 15/30 秒 | 实际发送档位、当前模型映射、可验收片长，不能只有提交成功 |
| 账号池 | 可追踪选择和明确拒绝后的切换 |
| 无账号/无额度 | 明确原因，没有假 loading 无限转圈 |

该测试入口是用户本次明确要求；无需把整个后台“模型渠道”模块改造成测试中心。

## 8. Canvas 生成

### 8.1 模型与参数

从已保存逻辑模型目录展示 `Dola / Seedance 2.5`、`Dola / Seedance 2.0 Fast`，不接入 1.0。参数弹层读取当前模型的独立能力档案。在现有 `canvas-video-settings-popover.tsx` 与共享 preference fields 中接通离散选项，不能只改一个下拉菜单却让服务端仍钳制为 10。

两个模型分别完整适配 `1:1、3:4、4:3、9:16、16:9、21:9` 六比例。时长独立联动：2.5目标5/10/15/30秒，Fast目标5/10/15秒、上限15秒；从2.5的30秒切Fast时必须提示重选并阻止提交，不能静默降为15。Fast15秒是用户明确需求，当前仍需成片验证。沿用模型切换联动：合法旧值保留，不合法旧值提示重选且阻止提交；能力加载失败不回退成通用全选项。Canvas、管理员测试和最终服务端校验共享 profile。Dola 只支持固定比例时不开放任意像素输入；不得静默裁切成片。详细数据流与用例见 [06 §6](06-协议实测报告.md#6-比例联动的详细需求补丁)。

需要逐层检查：模型目录 → normalizer/store → 公共 API 目录 → 逻辑模型 resolver → Canvas 设置 → 配置节点 metadata → 视频任务请求 → Agent 规划 → 最终 Provider body → 持久恢复。任何层默认时长覆盖都要测试。

用户显式选 30 秒必须到上游仍为 30；普通任务的上游拒绝直接显示真实错误。其他渠道参数不被 Dola 规则污染。尺寸/画质没有真实能力时不给假输入；不新增平台统一像素上限。

### 8.2 图片引用

复用现有连线资源和富文本 token。节点 A、B 即使同名也按稳定 ID 区分；改名不破坏引用；删除被引用节点在提交前给出明确提示；重复引用同一图不重复上传。

用户可：上传图片节点 → 连到视频配置/生成节点 → 输入引用图的提示词 → 选 Dola 模型和参数 → 生成。提示词中的可视 token 必须转换成真实图片绑定，不将本机 data URL、节点 ID 或 `@图片名` 误当上游资产。

如果上游当前只接受普通参考图，隐藏首尾帧快捷方式；已保存不兼容角色时提示纠正，不静默改角色。确认支持后复用首帧/尾帧两个独立槽位，防同图和缺帧。

### 8.3 生成结果与恢复

复用现有 pending/failed 占位与真实媒体比例，保留稳定任务 ID/结果槽。刷新、离开再返回、Worker 重启后回到原节点；不能追加同名第二个节点或重复发 Dola 创建请求。

显示公开模型、比例/时长、生成时间和状态；内部账号和执行 prompt 只在具权限的管理日志出现。结果保存在服务端并以站内 media URL 展示，下载原片不走浏览器直连 Dola CDN。

## 9. Dola 去水印节点

### 9.1 自动关闭时

仅当源视频由服务端登记为 Dola 生成、属于当前用户、有可读取源文件、没有正在处理的同等任务时，在单视频节点右键菜单显示 **Dola 去水印**。不是 Dola、未完成、图片/音频或上传来源不明的节点不显示；后端仍须独立验证。

处理首选07已验证的URL版本提取；缺少原生成元数据时通过原账号查原结果，无法恢复则明确失败，不静默改为局部修复。前台不要求用户输入签名地址，也不宣传“任意URL解析”。

点击后立即创建相邻派生视频节点，标题 `Dola 去水印`，与原节点连线。使用既有 `resolveCanvasNodePlacement` 避免覆盖其他节点。派生节点有真实尺寸占位、处理阶段、可用时的真实进度和停止入口；原节点保持可播放/下载。

客户端 metadata 示例（拟扩展，服务端归属才可信）：

```ts
{
  derivedVideoOperation: 'dola-watermark',
  derivedFromNodeId: sourceNode.id,
  sourceStorageKey: source.storageKey,
  processingTaskId: task.id,
  method: result.method, // source-url 或明确启用的本地修复
  resolverRevision: result.resolverRevision,
  status: 'loading'
}
```

节点插入和任务建立要有幂等关系：双击、快速多次右键、两个标签页操作返回同一处理中任务；Canvas 服务端按 `projectId + processingTaskId` 去重派生节点。新节点未持久化就刷新时，由服务器任务上下文补回一次，不能只在内存里保留。

### 9.2 自动开启时

新生成任务保存自动处理快照。原视频成功后自动建立唯一去水印 render 子任务；Canvas 展示原节点和相连派生节点，派生任务先为处理中，成功后成为可用清理视频。前端不依赖页面常开触发自动任务；由服务器完成创建。

无需自动处理的历史原片仍可手动；关闭开关后不追溯终止已创建后处理。已存在自动处理任务时右键显示“查看去水印任务”，不能再建重复任务。成功的清理片不再出现相同去水印入口。

### 9.3 失败、删除和重试

- 原视频成功而处理失败：派生节点显示具体错误、保留“重试去水印”和原片访问；不得重新调用视频生成或退回用户全部创作需求。
- URL元数据过期只查原结果，不重新生成；源账号失效或无法恢复时说明原因。
- 本地修复未可靠识别水印：显示“未检测到可处理水印”或“需要复核”，不要仅用文件存在判完成。
- 取消：结束本地处理和清理临时文件；不删除原视频。
- 删除源节点：不自动物理删除仍被处理任务引用的源媒体；基于服务端引用生命周期处理。是否删除派生节点遵守已有 Canvas 删除语义。
- 删除派生节点：不影响原节点；活跃任务按明确取消动作处理，不能因 UI 不再显示就遗留不可见任务。
- 失败重试沿用派生节点和业务操作身份，仅增加后处理 attempt；再次生成原视频必须是独立用户动作。
