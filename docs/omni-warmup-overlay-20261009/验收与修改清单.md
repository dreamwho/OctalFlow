# Omni warmup 遮罩拦截修复

用户日志证明错误发生在 warmup 的文本 Run 点击阶段：按钮被 `.dialog-backdrop-blur-overlay` 拦截；日志中的第一个 Close handler 完成后仍有遮罩。仅凭该日志不能确认剩余弹窗的身份，也不能认定 Omni 视频已提交。没有本次服务器任务 ID、现场 DOM 或原始 Provider 记录，不能声称现场剩余弹窗已被确认。

## 协议与执行方式

Canvas 通过 `/v1/videos` 向 GeminiAI Provider 创建任务；Provider 的 `OmniVideoRunner.run` 仍通过 Camoufox 浏览器执行 warmup、选模型、参数、参考图、提交与下载。本地协议封装不代表已经实现 Google 原生视频提交协议。代码中的 warmup 会提交一次文本生成，真实运行可能消耗文本额度；这次修复没有主动发送真实生成请求。

## 修复与证据

旧实现用全页面 JS 点击可能隐藏的按钮，常驻处理器固定取第一个 Close；真实 Chromium 夹具在修改前复现 5 项失败，其中隐藏旧按钮与多层遮罩复现相同指针拦截。新实现定位最后一个可见弹窗，正常点击其明确 Close/Close guided tour，等待该关闭按钮隐藏，再依据当前状态继续处理下一层；不使用 force、删除遮罩或新增固定等待/重试上限。处理器只在填写/提交作用域启用，正常模型选择保持可操作。

[Playwright 官方说明](https://playwright.dev/python/docs/api/class-page#page-add-locator-handler)明确 handler 会在动作可操作性检查时触发；本实现使用作用域内 body handler 和 `no_wait_after`，由正常 locator 动作及可见状态检查完成关闭。

条款即使有 Close 也不会自动关闭或接受；没有已知关闭入口的遮罩返回 `AI Studio dialog blocks submission`，提示手动进入该账号 AI Studio 处理。修复后新增场景均通过，但真实现场弹窗尚未验收。
