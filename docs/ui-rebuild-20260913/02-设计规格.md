# 可执行设计规格

以下为本次确定的产品规格，不是上游能力限制。Luna 按表实现，遇现有业务约束不能容纳时先调整本地布局并记录原因，不扩大所有共享控件。最终量实际 DOM 和图像像素；不可只数 className。

浅色面板正文区应实色或接近不透明；不让粒子视频影响输入区域对比。常规面板16px圆角，输入主面板20px；密集字段8–10px；Canvas媒体沿用已有圆角并让选中框一致。色彩目标必须验证合成后的对比：普通文本至少4.5:1，重要图标/可见焦点至少3:1。B01按钮中若白字处对比不足，只在文字承载区域微调底板蓝色强度并保留B01风格，记录比较结果；禁用态仍需可辨，不能靠几乎透明隐藏内容。

## C. B01生成按钮资产与布局

源图：`evidence/09-generation-button-v21.png`。它是真实有Alpha的1774×887图，不是黑底图片。外部透明留白与光晕不得计入按钮本体高度。保留原图；新增资源拟放 `web/public/brand/dreamyo/generation/`：
- `button-reference.png`：源图副本，仅设计对照，不进入每个按钮的img。
- `button-surface.png`：无烘焙文字、无星图的透明底板，保留B01蓝、青/薄荷、淡紫方向、白色内缘和受控光晕。
- `generate-glyph.png`：由B01派生的单个白星+圆点，透明紧边界，不包含文字/底板，至少96px素材用于18/20px显示。

图像编辑必须使用可用的图像编辑工具，附B01原图与“只分离内容，保持B01原轮廓/颜色/光晕及C01的蓝青薄荷淡紫关系”约束；不要手绘SVG仿图、截取模糊局部冒充清晰图标、把整张图片用CSS滤镜伪装透明。优先从设计目录找同源拆分资源，找到后验证同源与轮廓；若无法得到清晰独立资源，该资源任务保持BLOCKED，不能默默回退magic.png。

底板使用可伸缩的背景层保留两端圆角与中间颜色过渡：如果资源不适合9-slice，不允许硬拉伸；生成适合目标比例的无文字底板。宽按钮不放大星和字体。白星与所有“生成/开始生成/生成中/停止生成”均独立布局和无障碍名称，文案使用DOM，不能与烘焙文字重复。背景层pointer-events:none；按钮仍是原来的真实button、真实事件与状态。

拟为现有 GenerationActionButton 增加 `density="compact"|"standard"`，默认standard；继续使用现有appearance和block，不另造三层包装或新全局状态：

|场景|appearance/density|本体尺寸（Canvas为100%局部CSS像素）|图标/文字|父布局要求|
|---|---|---|---|---|
|/create发送、Canvas Agent发送|icon/standard|44×44|20px白星；无可见文字，aria-label发送/生成按现有语义|按钮独立flex:none，工具区可滚动|

## D. Logo

默认按图形+DOM品牌字标布局；全站默认图形同源，浅深为清晰合成资源，自定义Logo沿现有配置。导航图形视觉28–32px，助手24–28px，折叠侧栏24px，登录40–48px；资源本体不要仅占盒子一小角。
排查顺序：currentSrc与站点配置 → 源图Alpha/内部残留 → 容器background/pseudo-elements → 祖先filter/mix-blend → 缓存。外层负责尺寸、内层仅size-full object-contain，不能把drop-shadow尺寸class同时套外层与img。清除阴影不能替代真正透明素材。深色自定义资源优先于通用资源的契约需测试，Logo失败各自回退不互相污染。

## E. Canvas几何

1. 媒体原始比例和后端数据不改；选中视觉附着真实媒体壳外缘，不能把媒体缩小来迎合边框。
2. 移除100坐标系中按百分比内缩的选择rect。优先复用现有CSS边框层；如果继续SVG，采用真实像素宽高/圆角与描边外缘计算，不写固定百分比。现有SVG几何可维护，不新画品牌图标。
3. 边框装饰层absolute、pointer-events:none；媒体裁切只在媒体层，端口、resize handle和toolbar位于不裁切的层。选中框不包入提示输入面板或悬浮工具栏。
4. CSS边框1–2px，视口缩放后读取实际外缘。几何误差上限1屏幕CSS px，分别测左上右下；SVG根节点rect等于媒体不代表笔画外缘等于媒体。
5. 25/50/75/100/150/200%为测试采样点，先核对当前真实缩放范围，不新增缩放能力；不存在的采样点用现有允许的最近值并记录。

## F. 浅色背景与首页结构

保留真实页面结构：导航 → 标题/副标题 → 输入面板 → 快捷场景 → 下方内容。冷白底清晰，按C01分布的蓝、青/薄荷、淡紫动效位于品牌留白区；不能让全屏灰雾、深色素材或高强度粒子覆盖正文。浅色标题/输入不施加filter/backdrop-filter；背景最多两层transform/opacity动画，所有blur固定在已验收的预渲染资源内，不运行时糊整页。保留轻动效，不以删除所有背景作为完成。

首页输入、快捷面板、Skill/模型选项、模式组分别有浅深表面变量；下拉Portal主题不能仅依赖父div。移动端页面左右16px，面板内16px，工具间8px，发送独立；桌面输入面板最大1080px，内20px，hero留白随viewport调整，不沿用固定760px首屏高度到手机。

## G. 后台四个可复制模板

无专用后台设计板，以C01派生的同色系与真实业务构建，禁止用一张总览图代替页面：
- 框架：六职责组，桌面侧栏可折叠；<1024按既有断点抽屉；移动顶部只菜单与常用操作，标题在内容区。Logo与用户端同源。
- 看板：页标题/时间筛选 → 4项实际指标网格（手机2列）→ 图表/近期记录。无数据时显示清楚的空态，不虚构数据。
- 列表：标题+创建 → 可换行筛选条 → 表格/手机卡片 → 分页；字段显示优先级为主体、状态、关键业务值、更新时间、操作，具体字段沿真实模型。新增/编辑进Modal/Drawer。
- 配置：标题/当前状态 → 分组卡片 → 紧凑字段网格 → 保存反馈。短字段desktop2–3列，手机1列；密钥/证书通栏，脱敏；Drawer max-width:100vw、底部动作完整。

36分区每个都验证列表/表单/弹层/主题，第三方配置如未授权必须保留明确状态；绝不把六个代表分区等同全部后台验收。头像公开ID格式、按需预加载、保存删除即时持久化和权限继续遵守AGENTS.md。
