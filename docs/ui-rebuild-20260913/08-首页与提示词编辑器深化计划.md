# 首页、`/create` 与 Canvas 提示词面板深化计划（2026-09-15）

## 目标与参考优先级

本批次处理首页、`/create` 创作入口的页面视觉，以及 Canvas 节点提示词面板的交互与视觉。结构与业务行为以现有项目为准，视觉层级以本批次 01—08 设计图为准，颜色继续使用 C01 的蓝、青、薄荷、浅紫语义体系。01 与 02 的源文件字节相同，但分别作为首页和 `/create` 初始态的视觉语言参考；03—05 定义 Canvas 提示词面板浅色状态，06—08 定义 Canvas 提示词面板深色状态。用户于 2026-09-15 补充确认：提示词深化设计主要落在画布页面，`/create` 不承担本批次完整的行内 Token 重建。

参考文件位于 `evidence/20260915-home-create-prompt/reference/`。附件中的文字只作为视觉示例，产品文案、模型、Skill、图片和数量必须来自现有真实数据。

## 保留的产品契约

- 保留附件草稿只驻留页面内存、发送时才上传的现有流程。
- 保留 `/create` 的 Agent、图片、视频、音频四种创作模式，模型、参数、Skill、引用、优化、取消和提交继续调用现有回调。
- 保留 Canvas 节点按类型生成、模型和参数设置、引用素材、Skill、镜头控制、放大编辑、停止生成与现有持久化协议。
- Canvas 提示词保留 `@` 图片/视频/音频/文本引用、`/` Skill 搜索、Enter 提交与 Shift+Enter 换行，并升级为真实行内 Token 编辑。
- 保留视频首帧/首尾帧专用槽位和提交前校验。
- 页面文案保持中文；设计图中的模型名、数字、头像和示例图不写成固定假数据。

## 实施卡

### HCP01 基线与变更边界

- 读取目标文件现有 diff，不覆盖用户或前序任务修改。
- 保存当前首页桌面基线；实现完成后补齐首页与 `/create` 的浅色/深色、1440、390、430 截图与测量 JSON。
- 本批次只允许修改首页、`/create` 页面视觉和 Canvas 提示词面板调用链；不得改后台、ChatGPT API 修复、数据库或外部服务配置。

### HCP02 首页首屏信息架构

- 将首页首屏组织为品牌 Hero、主创作输入、快捷场景入口三层；桌面同屏能看到主输入和快捷入口，移动端首屏至少看到主输入与第一组快捷入口。
- 标题调整为“让想象发生 / 创意因 AI 而更闪耀”语义，副标题说明图片、视频、设计与文字等真实能力。
- 使用现有 dreamyo 透明 Logo、`flow-light.png`、`flow-dark.png` 和真实站点设置；不得重绘 Logo 或复制参考图里的署名、英文装饰文案。
- 控制背景清晰度，浅色主题不出现灰雾遮罩；深色主题维持可读对比。

### HCP03 首页内容区

- 依次呈现快捷开始、核心能力、四步流程、灵感作品、底部 CTA；复用真实路由和已有数据，不创建静态假作品。
- 卡片采用紧凑白色/深蓝玻璃面、12—18px 圆角、细描边与弱阴影，颜色只承担层级与状态。
- 空数据或请求失败继续呈现真实状态，不能用设计图素材伪装内容。

### HCP04 `/create` 初始态与工作区壳层

- `/create` 空白初始态沿用首页的品牌色、背景清晰度和卡片层级；进入对话后保留现有对话/结果布局。
- 输入区成为页面主视觉，不重复显示同级标题，不遮挡历史、资产面板或消息滚动区。
- 弹层在空白初始态向下展开，进入对话后向上展开，继续按 `visualViewport` 限高。
- `/create` 继续使用既有输入与附件语义；本批次不要求把 Canvas 的完整行内 Skill/图片 Token 编辑器复制到 `/create`。已产生的通用编辑器代码只有在不改变 `/create` 现有业务契约、且能被 Canvas 真实复用时才保留。

### HCP05 Canvas 提示词行内文档模型

- 在 `CanvasNodePromptPanel` 调用链中使用项目已有 TipTap，增加轻量行内 atom 节点：`skillToken` 与 `referenceToken`。节点必须可以位于任意文字位置、随文字自然换行、支持键盘前后移动和 Backspace/Delete 删除。
- `skillToken` 保存稳定 Skill ID 与显示名；提交时仍通过现有 `skillIds` 参数传递，公开提示词和上游执行提示词不得包含内部 Token 标记。通过顶部选择器或 `/` 选择 Skill 时在当前光标处插入；删除 Token 必须同步移除选中 Skill。
- `referenceToken` 保存稳定 Canvas 引用节点 ID、资源类型、当前引用标签和预览 URL；提交仍序列化为现有 `@标签`/Canvas 引用协议，不能依标题文本匹配节点。通过顶部引用入口或 `@` 选择时在当前光标处插入。
- 编辑器对外继续输出现有字符串 `prompt`，不能更改 `onGenerate`、`onPromptChange` 或 Canvas 持久化接口；行内文档负责把 Token 与现有字符串协议无损往返。节点切换、外部状态恢复、生成成功清空和展开/收起编辑器必须安全同步同一文档。
- 不能以“透明 textarea + 不可交互覆盖层”作为最终方案。

### HCP06 Canvas 行内 Token 视觉与操作

- 图片 Token：真实限宽 WebP 缩略图、`图片 N/视频 N/音频 N`、关闭按钮，基线与正文对齐，边框只包 Token 本体；文本引用使用单色文档图标和真实编号。
- Skill Token：Lucide `Sparkles`、Skill 名称、关闭按钮；浅色用淡紫/淡青底，深色用低透明蓝紫底和清晰描边。
- Token 高度 32—38px，正文桌面 16—18px、移动端 15—16px，行高至少 Token 高度 + 8px；中英文标点不得被 Token 挤出形成异常孤行。
- 删除按钮具备可访问名称，触控命中区不小于 28px；键盘删除与点击删除得到同一状态。

### HCP07 Canvas 面板结构与控件

- 顶部：引用数量、提示词库、Skill、镜头/参考状态和放大编辑入口；只显示当前节点类型真实可用的状态。
- 主体：正文、图片引用和 Skill Token 在同一真实编辑流中，不再另起独立上下文条重复展示已经插入的 Token。只有尚未插入但可引用的素材入口可以作为辅助选择源。
- 底部：模型、参数、积分摘要和生成按钮继续使用现有真实行为；必要的插入入口放在顶部或紧凑工具区。窄屏工具横向滚动，生成按钮固定可见。
- 普通 16—20px 工具图标统一 Lucide 单色；模型品牌图标沿用现有平台图标。
- 生成按钮使用现有清晰 B01 衍生样式与 `GenerationActionButton`，桌面标准 44px、紧凑状态 40px，图标清晰且不裁切。

### HCP08 Canvas 浅深主题与状态

- 浅色：正文 `#13213f` 附近、弱文 `#637394` 附近、紫蓝 caret；面板白色玻璃，青蓝细边。
- 深色：正文接近白色、弱文不低于中灰蓝、紫色 caret；面板为深海军蓝玻璃，边框蓝紫可辨。
- 补齐 hover、focus-visible、disabled、busy、error 状态；不得用新增全局 `!important` 或 `overflow:hidden` 遮盖问题。

### HCP09 自动化与生产门禁

- 为 Canvas Token 字符串往返、任意位置插入、引用/Skill 删除、外部值同步、展开/收起同步和提交清理增加 Vitest。
- 更新现有首页、`/create` 和 Canvas prompt panel 测试，验证保留的按钮、模式、参数、Skill、引用和生成回调。
- 依次运行目标 Vitest、`pnpm typecheck`、`pnpm build`。每次最终代码变更后重建并重启生产 `pnpm start`。

### HCP10 真实浏览器设计验收

- 使用 Codex 内置浏览器，在隔离测试数据下实际登录，检查 `/`、`/create` 与动态真实 ID 的 `/canvas/[id]`。
- 视口：1440×1000、390×844、430×932；主题：浅色、深色。首页检查首屏与下层入口；`/create` 检查空白和进入对话的页面壳层；Canvas 检查纯文本、行内图片、行内 Skill、混排、多行换行、放大编辑、disabled/busy。
- 测量 Canvas 正文、Token、工具栏、生成按钮、节点与面板边界；断言无横向溢出、无裁切、caret 可见、点击命中正确、Token 删除后真实状态同步。
- 根目录 `design-qa.md` 逐项记录 reference、implementation、差异、修复和证据。P0/P1/P2 全部清零后才写 `final result: passed`。
