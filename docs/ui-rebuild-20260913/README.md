## 3. 为什么旧计划没有兑现

- 旧计划写了“全站”“透明”“清晰”，却把小尺寸资源、控件尺寸留到现场决定；执行者用彩色展示 PNG 替换高频工具图标。
- 首页与 `/create` 是两套组件，修改一处不能证明另一处正确。首页浅色 `--hero-panel` 仍是深色；创作页正文仍受无主题限定的深色强覆盖影响。
- 全局生成按钮、产品设计覆盖、Canvas 覆盖与调用方 Tailwind 同时控制尺寸；`48px` 固定按钮进入 `h-12 + border + pt-1 + overflow-hidden` 底栏导致冲突。
- 选中框 `viewBox 0 0 100 100` 内的 `x/y=0.8`、`width/height=98.4` 会按节点尺寸内缩，无法紧贴不同大小的图片外缘。
- 先前报告只证明部分路线可打开、少数元素数量和页面无横向溢出；这些证据无法证明输入可见、图标清晰、局部不裁切、全部后台与手机端通过。
- 没有截图文件、状态标记、视口及对应源码版本的 PASS 一律撤销；旧 Vitest 数字只是当时测试结果，不能证明本轮修复已完成。

## 4. 不再留给 Luna 猜测的决策

- Canvas 工具栏、参数、编辑、引用、上传等 16–20px 操作图标统一使用现有 Lucide 线性图标；图片/视频/音频文件插画仅用于大入口、空态或无真实缩略图的类型标识，不混在同一工具栏。
- 所有生成动作参考B01 的“蓝→青/薄荷→淡紫胶囊表面 + 白色四角星/圆点 + 按场景显示文字”。禁止继续用 `magic.png` 的模糊小插画或用积分 Sparkles 冒充生成图标。
- B01 整图含透明留白与烘焙文字，不能直接塞进 18px 图标槽，也不能拉伸整图制造超长按钮。先制作并验收B01 的无文字底板和独立白星派生资源，再接入真实 DOM 文案。完整原图保留为设计事实。
- 浅色背景不用深色粒子视频叠白雾。先从现有浅色资源中选取通过清晰度检查的品牌背景；没有合适成品则按同一设计板生成专用浅色抽象背景。背景以少量层的位移/透明度实现轻动效，正文不参与模糊与混合。
- 默认 Logo 必须无可见矩形背景、无黑白底块；不把“文件有 Alpha”当验收通过。支持后台通用/深色资源及失败回退，保留自定义配置。
- 样式所有权固定：Ant 主题由 `app-theme.ts` 管理；Canvas 色值由 `canvas-theme.ts` 管理；生成按钮由共享组件和 `global-generation-actions.css` 管理；首页/创作页私有布局在各自 module.css。`global-product-design.css` 只保留真正跨页面的规则，不再用新增全局 `!important` 修补局部错误。
