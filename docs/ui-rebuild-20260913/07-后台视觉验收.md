# 后台管理视觉验收与设计素材映射

本轮后台改版按用户指定的 C01 配色图作为全站色域依据，按 `全新UI设计/后台管理/` 的信息层级和组件参考图落实到现有真实业务组件。后台没有单独的 Figma 页面，因此采用“设计素材 → 真实组件 → 真实接口状态”的映射方式；原始 PNG 只作为设计事实和验收参考，不直接铺成页面背景，也不把设计图里的示例数据写入生产数据。

## 素材读取结论

已读取后台管理目录下 23 张 PNG，并记录尺寸、Alpha 通道、内容边界、SHA-256 和应用位置到 `后台设计素材映射.csv`。素材分成四类：

- 框架：总览设计板和 `左侧导航栏.png`，确定 Logo 锁定区、六组职责导航、渐变选中态、后台品牌卡和主内容层级。
- 看板：KPI、调用趋势、用户/权限、计费配额、插件中心、API 设置，分别对应总览、用户、财务、上游和系统分区的可复用信息卡。
- 运营状态：`模型状态列表.png` 和 `任务列表.png`，对应真实模型渠道健康、任务状态、失败/等待/进行中语义，不复制示例模型名、图片或百分比。
- 组件与按钮：筛选栏、表格工具栏、分页、行操作菜单及 8 个按钮状态。按钮的动态文案继续由 DOM 生成，C01 渐变和状态由后台共享 CSS 承载；PNG 不被缩放成模糊的动态按钮文字。

## 本轮真实改版

### 全局框架

`AdminSectionNav` 已变为 C01 玻璃冷白/深蓝侧栏，保留六个职责组和权限过滤；品牌锁定区统一显示 `dreamyo / 管理后台`，选中项使用蓝→青→淡紫渐变、白色线性 Lucide 图标，非选中图标保持单色。桌面侧栏宽 220px，移动端继续使用不超过视口的抽屉；底部品牌卡只承载品牌文案，不创建业务数据。

### 总览看板

`AdminDashboard` 的标题区改为轻量渐变信息卡，四项指标卡采用 C01 的冰青/薄荷光晕和统一边界。`AdminOverviewOperations` 从 `/api/admin/generation-operations?page=1&pageSize=4` 读取真实渠道与任务，新增“模型服务状态”和“任务队列”双栏快照：

- 模型行显示真实逻辑模型、能力、上游模型及健康/冷却/停用状态。
- 队列行显示真实任务摘要、模型、类型、状态和语义进度；运行中采用连续进度动画，终态只显示真实完成/失败/取消，不伪造百分比。
- API 或外部服务不可用时显示可读错误态；零数据显示可读空态，不能用设计图样例冒充已接入数据。

### 生成运维

`GenerationOperationsClient` 保留真实筛选、分页、取消、重试和接管调用，统一包裹 C01 主题。`GenerationChannelStatus` 改成带能力图标、健康语义和绑定明细的卡片行，状态标签使用正常/冷却中/已停用的浅底细描边；没有合理的彩色品牌图标时使用 Lucide 单色图标。

## 当前验收结论

- 已通过：后台主壳在 C01 浅/深主题下真实渲染；侧栏选中态、Logo 背景透明、标题卡、KPI 卡、模型状态空/真实行、任务队列空/真实行容器、生成运维筛选表格均有视觉截图和实际 DOM 边界。
- 已通过：390px/430px 总览无横向溢出，移动导航仍为抽屉，按钮未越过视口；桌面侧栏实际宽度 220px。
- 已通过：C01 浅色使用冰白→青→淡紫渐变，深色使用深蓝→青紫表面；总览 KPI、商业转化、模型状态和任务队列层级一致，渠道状态卡在桌面单列铺满可用宽度，窄屏保持 2 列 KPI 且无横向溢出。
- 已通过：后台设计图中的侧栏职责分组、底部品牌卡、模型状态和任务队列信息层级均映射到真实组件；模型/任务内容来自 `/api/admin/generation-operations`，没有把 PNG 示例数据写入业务。
- 仍需补充：其余后台分区的真实数据状态、外部授权页面、财务 PostgreSQL 摘要和第三方渠道操作必须分别使用对应隔离夹具验收；不能用总览截图替代 36 个分区的逐项通过。
