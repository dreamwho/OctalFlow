# 画布比例与 DOLA 修复验收记录

开始日期：2026-09-30；完成日期：2026-10-01。范围：本轮三个 BUG；既有工作区改动保留。生产 BUILD_ID：`vwVjeQ3SCDEKz8nUgIQCJ`。

## 结果与原因

1. 已完成图片节点的 16:9 配置曾在提交时被原始 9:16 参考图覆盖，因为节点没有 `sizeUserSelected` 标记。现在再次生成使用当前节点显示的尺寸；本轮文字明确要求尺寸仍优先，精确自定义尺寸和智能比例继续沿用既有规则。
2. DOLA 曾只在失败状态中判断额度错误，漏掉 HTTP 200、accepted 但正文表示当日额度已达上限的响应。公共 Provider 入口现在进行语义识别，写入当日耗尽标记；画布提交链按管理员已有换号预算选择其他账号。无可用账号或换号预算用完时返回真实额度失败。
3. 取消记录曾允许被迟到的 accepted 查询覆盖。现在取消是独立终态，文件存储和 PostgreSQL UPDATE 条件均保护该状态；管理员查询统一复用原提交记录，取消同时终止同一任务已有日志；后台列表和详情即时同步，刷新后仍为已取消，并保留原 HTTP 响应码。
4. 截图复核发现详情抽屉在窄屏仍按桌面宽度定位，已改为实际宽度不超过视口；390px、430px 检查抽屉和内容区边界。

## 额度语义

- 实际读取“将消耗 2 个视频生成额度”和“今日剩余 2 个视频生成额度”，记录单次成本 2、剩余 2。
- 当天按稳定任务 ID 去重记录已观察消耗；轮询同一任务不会重复累计。
- 只看到上述一次回复时，日总额度仍为未知；已观察总额度下界为 4，不把它宣称为完整日总额，也不写死每日次数或每个模型的成本。
- 视频余额不足该模型已观察到的单次消耗时不参与该模型调度；图片和视频余额按各自能力判断。
- 跨服务器配置的自然日后忽略旧额度；查询昨天的任务不重新计入今日额度。登录检测的未知额度也不会擦掉当日观察值。
- 有真实图片或视频结果时以真实媒体结果为准；额度文字不把已经交付的媒体改判成额度失败。
