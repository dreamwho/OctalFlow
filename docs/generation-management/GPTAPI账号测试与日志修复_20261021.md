# GPTAPI 文本/图片账号测试与日志修复

## 本次行为

GPTAPI 账号列表新增“文本测试”和“图片测试”。点击后选择当前目录中的模型、编辑提示词，手动点击“开始真实测试”。只调用所选账号，不自动切换账号或重发请求；禁用账号不能测试。真实提交会使用上游账号额度。

结果显示成功/失败、实际返回的文本或图片、耗时、错误码和调用 ID。文本为空或图片为空都属于失败；HTTP 200 中的业务失败不会显示为成功。图片通过带签名的站内相对链接展示限宽 WebP，避免容器的 `0.0.0.0` 地址泄漏到浏览器，也不修改源文件。调用 ID 对应请求日志记录。

旧版图片兼容目录继续保留；Flare/Sunburst/exact 名称仍沿用之前确认的兼容行为，不宣称独立选型。获取目录和测试不会自动同步模型渠道。

## 本次错误的判断

用户提供的请求 `ae1d80c9b987486e` 已建立会话并收到上游流数据，最后未返回图片，日志记录 `no_image_generated`，可见的上游内容为仅有 `prompt` 的 JSON。这不足以确定账号失效、代理中断、图片工具是否执行，或具体型号不可用。

代码确认原 `stream_error_ms` 会在所有失败异常中按已耗时间赋值，正常结束后的语义失败也可能被标为“上游断流”。本次将既有重试判断所需的流耗时与真实断流指标分开：只有传输/超时异常或带有真实断流证据的恢复异常才显示断流指标。不会因此自动增加重试、延时或重新创建上游任务；既有会话恢复仍沿用原会话。只修正新调用，历史日志不改写。

本次不声称修复了上游图片工具自身错误。新增测试用于分别复核同一账号的文本和图片返回，并保留真实结果。

## 上传并更新

将这两个文件上传到 `/opt/www/dreamyo/`：

- `dreamyo-gptapi-tests-update-20261021.tar.gz`
- `dreamyo-gptapi-tests-update-20261021.tar.gz.sha256`

只执行下面的更新命令，不要把回滚命令一起执行：

```bash
cd /opt/www/dreamyo && \
sha256sum -c dreamyo-gptapi-tests-update-20261021.tar.gz.sha256 && \
mkdir -p updates/gptapi-tests-20261021 && \
tar -xzf dreamyo-gptapi-tests-update-20261021.tar.gz \
  -C updates/gptapi-tests-20261021 && \
bash updates/gptapi-tests-20261021/本次修改需上传文件_20261021/scripts/deploy-gptapi-tests-update.sh \
  --compose /opt/www/dreamyo/docker-compose.offline-external-db.yml \
  --project-dir /opt/www/dreamyo
```

更新完成后刷新后台 GPTAPI 页面，在指定账号上点击“文本测试”或“图片测试”，选模型并手动开始。测试不会自动触发。如果上游仍没有图片，页面应显示失败及调用 ID，而不是误报测试成功。
