# GPTAPI 更新权限修复

本次更新前的 EACCES 原因为公开预览图 `web/public/skills/previews/character-casting-studio.png` 保留了 0600 权限。以 root 运行的旧测试及 macOS Docker Desktop 共享目录未发现非 root 权限问题；在真实容器文件系统中，以 root 所有、0600 权限复现 EACCES，改为 0644 后 UID/GID 1000 完整读取并核对旧版 7790 个、新版 7800 个 Web 运行文件均通过。

只调整该预览图的文件权限，不改文件内容、Build ID、哈希、数据库或容器用户，不跳过完整基线校验。已上传旧包的服务器需同时修复 App/Worker 当前受管理 Web 挂载内的这张图片及上传目录 runtime/web 内的同一图片，然后重跑原安装脚本。当前失败发生在 baseline 校验阶段，未切换服务。

修正版归档为 dreamyo-gptapi-tests-update-20261021-permissions-fixed.tar.gz；原始归档保留用于追溯。

修改文件：

- web/public/skills/previews/character-casting-studio.png：权限从 0600 改为 0644，内容不变。
- runtime/web/public/skills/previews/character-casting-studio.png：运行包内同步改为 0644。
- docs/generation-management/GPTAPI更新权限修复_20261021.md：记录根因、修复范围和非 root 验收结果。
