# GPTAPI 模型目录与运行包更新

本包在本地使用 Linux x64 / Node 22.23.3 构建 Web standalone，并携带 GPTAPI 的 9 个 Python 覆盖文件。服务器直接校验、暂存、切换运行目录和重建三个容器，无需下载依赖、编译或构建完整镜像。

## 功能与错误结论

- GPTAPI 后台点击“获取上游最新模型”，自动选择一个正常、可用且不处于待核验状态的账号；获取失败不改选其他账号。显示账号来源、接口与获取时间。
- 使用项目既有认证目录 `/backend-api/models?history_and_training_disabled=false`，只保留真实返回的模型 ID。文本与图片分组，图片输入能力或图片工具支持不能直接当作图片输出模型。
- 上游没有返回图片型号时显示空类别及提示，不把本地预置型号标成最新。已保存但本次未返回的型号仍保留选择，需人工移出后才能同步；获取本身不修改渠道。
- 勾选后单独点击“同步至渠道与逻辑模型”。成功保存的认证快照在刷新和服务重启后保留；获取失败保留上次成功快照。普通 API Key 无权读取账号来源。
- 新发现的图片 ID 只在成功认证快照的图片白名单内放行，既有请求体保留该 ID；目录出现仍不等于型号实际可以生成。
- 已确认失效账号自动禁用与清理接口修复一并携带；临时网络/代理错误不会被当作永久失效删除。

本次只读核对服务器请求 `50316673799d46f0`：`/v1/images/edits`，6 张参考图、`1024x1536`、`quality=low`，4 次尝试 / 3 次换号，总计 40.2 秒；日志错误码为 `upstream_connection_failed`，响应数据为空。旧代码会把连接失败也显示成同一句 `The image generation tool encountered an error. Please try again.`，因此不能据此断定上游工具报错或账号失效。本包给连接失败/超时显示中文代理与网络提示，并保留原网络重试策略；明确的工具错误才停止盲目换号及无依据的账号核验。没有用公共错误文案覆盖已有连接失败分类。

没有发起真实账号的生图或真实目录请求，也没有改服务器代理。上游真实断连位置及更新后真实出图仍需服务器验收。

## 上传、解压与更新

将以下两个文件上传到 `/opt/www/dreamyo/`：

1. `dreamyo-gptapi-models-update-20261021.tar.gz`
2. `dreamyo-gptapi-models-update-20261021.tar.gz.sha256`

在服务器执行这一段：

```bash
cd /opt/www/dreamyo && \
sha256sum -c dreamyo-gptapi-models-update-20261021.tar.gz.sha256 && \
mkdir -p /opt/www/dreamyo/updates/gptapi-models-20261021 && \
tar -xzf dreamyo-gptapi-models-update-20261021.tar.gz \
  -C /opt/www/dreamyo/updates/gptapi-models-20261021 && \
bash /opt/www/dreamyo/updates/gptapi-models-20261021/本次修改需上传文件_20261021/scripts/deploy-model-catalog-update.sh \
  --compose /opt/www/dreamyo/docker-compose.offline-external-db.yml \
  --project-dir /opt/www/dreamyo
```

脚本检查基线与 Linux ABI，暂存到 `.source-update/releases/`，备份 Compose 后只重建 `app generation-worker chatgpt-api`，等待健康检查。未知基线会在切换前停止。成功后刷新后台，先获取、再勾选同步。

查看状态：

```bash
docker compose \
  --project-directory /opt/www/dreamyo \
  --env-file /opt/www/dreamyo/.env \
  -f /opt/www/dreamyo/docker-compose.offline-external-db.yml \
  ps app generation-worker chatgpt-api
```

## 中断后的继续操作

若本次脚本被中断，先执行这一段；脚本会检查事务记录，必要时恢复上一份 Compose 并重建服务，再继续已暂存的更新：

```bash
bash /opt/www/dreamyo/updates/gptapi-models-20261021/本次修改需上传文件_20261021/scripts/deploy-model-catalog-update.sh \
  --resume \
  --compose /opt/www/dreamyo/docker-compose.offline-external-db.yml \
  --project-dir /opt/www/dreamyo
```

## 回滚（独立操作）

需要撤销本次更新时，单独执行：

```bash
bash /opt/www/dreamyo/updates/gptapi-models-20261021/本次修改需上传文件_20261021/scripts/deploy-model-catalog-update.sh \
  --rollback \
  --compose /opt/www/dreamyo/docker-compose.offline-external-db.yml \
  --project-dir /opt/www/dreamyo
```

回滚恢复本次更新前的 Compose 和三个服务。中断恢复记录会保留到服务重建及健康检查完成；Compose 被外部流程改动时拒绝猜测覆盖。回滚不删除 release、数据卷、数据库或 `.env`。
