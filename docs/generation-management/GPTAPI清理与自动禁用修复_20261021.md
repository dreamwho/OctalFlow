# GPTAPI 清理接口与自动禁用修复

## 问题与修复

生产启动入口是 `services/chatgpt-api/main.py` 调用的受限 `api.app.create_app()`。上一包虽然添加了清理函数和 Web 转发，但没有在内部运行时白名单注册 `GET/POST /api/accounts/cleanup-abnormal`，真实请求返回 `404 {"detail":"Not Found"}`。原测试直接调用函数，浏览器测试又模拟了接口，没覆盖这个入口。

本次补齐两种方法的白名单；同时把清理固定路径放到账号详情动态路由之前，避免完整账号路由将 `cleanup-abnormal` 识别为账号 ID。测试改用完整 FastAPI HTTP 入口，并通过真实 Linux Web → 内部运行时 → SQLite 链路验证浏览器操作。

确认失效或封禁的账号自动保存为“禁用”，不再参与调度；已持久化为异常且有确定失效证据的账号会在加载时禁用。临时网络、TLS、代理故障、限流或未确认异常不会因此被强制禁用。原本手动禁用的账号继续保持禁用，既有显式自动移除配置的处理语义保留。

安装仅执行清理预览 GET 验证，不自动清理账号。点击“一键清理异常账号”仍需在弹窗确认后执行删除。

## 上传与更新

本补丁在之前的运行包更新完成后使用。将 `dreamyo-gptapi-fix-20261021.tar.gz` 上传到 `/opt/www/dreamyo/`，只执行下面的更新步骤：

```bash
cd /opt/www/dreamyo && \
mkdir -p updates/gptapi-fix-20261021 && \
tar -xzf dreamyo-gptapi-fix-20261021.tar.gz -C updates/gptapi-fix-20261021 && \
bash updates/gptapi-fix-20261021/本次修改需上传文件_20261021/scripts/deploy-gptapi-fix.sh \
  --compose /opt/www/dreamyo/docker-compose.offline-external-db.yml \
  --project-dir /opt/www/dreamyo
```

脚本校验三份旧文件的实际哈希和包内文件，以现有 GPTAPI Python 编译检查源文件，备份 Compose，仅切换三个 Python 文件挂载并重建 `chatgpt-api`，随后检查真实清理预览接口。App、Worker、其他服务和数据卷的配置不变。重复执行已安装补丁只验证接口，不重建容器。

不下载依赖，不重建或导入完整镜像。更新失败或常规信号中断会尝试自动恢复原 Compose 和 GPTAPI 服务。运行文件保存在 `.source-update/gptapi-fixes/`，不能删除。

## 仅需撤销本补丁时使用

下面是回滚命令，**不是更新完成后的下一步**。回滚恢复本补丁前的 GPTAPI 代码和挂载，不回滚账号数据或本补丁前已部署的 Web 版本。

```bash
bash /opt/www/dreamyo/updates/gptapi-fix-20261021/本次修改需上传文件_20261021/scripts/deploy-gptapi-fix.sh \
  --rollback \
  --compose /opt/www/dreamyo/docker-compose.offline-external-db.yml \
  --project-dir /opt/www/dreamyo
```

## 修改文件

- `services/chatgpt-api/api/app.py`：在生产内部运行时注册清理预览和清理接口。
- `services/chatgpt-api/api/accounts.py`：固定清理路径优先于账号 ID 动态路径。
- `services/chatgpt-api/services/account_service.py`：确认失效时持久化禁用，加载已有确认失效记录时禁用，保留临时错误和手动禁用的语义。
- `services/chatgpt-api/tests/test_account_cleanup.py`：通过实际 HTTP 路由、权限、列表、落库、刷新和重复请求验证清理。
- `services/chatgpt-api/tests/test_account_auto_disable.py`：验证已有和新增失效账号禁用、临时错误保留、手动禁用及既有自动移除配置。
- `scripts/deploy-gptapi-fix.sh`：只更新 GPTAPI 的小补丁安装、校验、备份、自动恢复和手动回滚。
- `scripts/deploy-gptapi-fix.test.sh`：回归 GPTAPI 单服务更新、失败与信号中断恢复、重复安装与重复回滚。
- `tools/yaml/`：上传包中随附现有 YAML 解析器及许可证，避免服务器安装依赖。
