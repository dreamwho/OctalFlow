# New API 图片尺寸配置与逗号输入修复

## 后台如何设置

进入「模型渠道 → 逻辑模型」，编辑用户实际选择的逻辑图片模型，在对应渠道绑定的「能力档案 → 支持尺寸 / 比例」填写上游明确支持的值，然后点击「应用修改」。前端重新打开页面或刷新后使用该绑定的尺寸档位。

- 固定像素尺寸填写 `1024x1024`；多个值可以使用英文逗号或中文逗号分隔，例如 `1024x1024,1536x1024`。第二个值仅在上游确实支持时填写。
- 比例填写 `1:1,16:9,9:16`。比例与像素尺寸含义不同，不要为了显示更多选项填入上游没有声明的值。
- 清空该字段并应用，前端恢复提供方或项目默认选项。
- 固定像素档位会在工作台、Canvas 图片设置及 Canvas Agent 图片偏好中保持精确数值；Canvas 的固定档位不额外展示自定义像素入口。GPTAPI 专用协议继续遵循其原有固定尺寸契约。
- 多绑定模型以前端当前选择的有效优先绑定为准；备用或其他上游通道不会扩大该绑定的尺寸范围。

截图 2 中 `size = 1024x1024` 仅表示文档中的默认值，没有给出完整允许值列表。若只能确认这一项，可先只填写 `1024x1024`，其余项向对应渠道确认后再添加。New API 是接入协议，不能单凭协议名称判断每个上游模型的尺寸能力。

## 问题原因与修复

1. 输入框每次输入都 split/filter/join，将刚输入的英文逗号作为空项删除。现在保留输入中的原始文本，持久值独立按中英文逗号拆分、去空和去重；视频清晰度字段同步修复。
2. 逻辑绑定的尺寸字段虽然可以持久化，但公开会话没有下发尺寸档位，前端工作台和 Canvas 使用默认选项，图片任务也没有通过该字段实施像素白名单校验。现在仅公开图片尺寸字段，继续隐藏成本、密钥和内部请求配置，再由当前逻辑绑定提供选项。
3. 像素档位原值传入任务 config.size，不转换成通用比例，也不通过图像缩放模拟该尺寸。最终上游是否接受仍以其实际响应为准。

本次没有修改真实渠道配置，也没有调用真实收费模型。源码更新包包含之前四项更新及本次补充，部署步骤仍见 `docs/deployment-source-update.md`。
