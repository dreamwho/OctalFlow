## 新的部署约束

`expected-build-id.txt` 改为已观测的线上 ID，同时新增 `expected-runtime-files.json` 和 `scripts/verify-source-update-baseline.cjs`。stage/apply 在切换前对 App 和 Worker 同时校验：

1. Build ID 精确匹配；
2. 镜像 ID 精确匹配（不依赖可变标签）；
3. 清单中 2361 个服务端代码、静态资源、脚本与路由清单文件存在且 SHA-256 匹配。

Build ID 文件和随机生成的 server-action 密钥清单不参与代码内容哈希比较；Build ID 另行精确校验，密钥清单不被复制为源码配置。额外旧构建孤立文件不参与此白名单，不根据它们推断有效代码。

## 更新方式

小型修正包只覆盖已解压上传目录中的必要文件，并提供该完整上传目录的新 `SHA256SUMS`。不修改服务器镜像、Compose、数据库或运行应用。覆盖后先校验完整目录，再执行原 `--stage`，成功后再执行 `--apply`；回滚命令不变。

此方式仍在服务器现有镜像内编译 Web 源码，不执行 `docker build`。目标服务器完整 stage/apply/rollback 尚待用户执行；本机编译与浏览器通过不等于已部署或真实上游验收。
