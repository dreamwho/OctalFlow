# Dola 桌面客户端与画布外部编排接口：可行性分析和实施计划

日期：2026-09-27。本文以仓库当前源码和用户提供的五张参考图为依据；参考图中的账号、时长和 API 示例不是 Dola 上游能力证明。

## 1. 需求边界与已有资产

| 目标 | 仓库现状 | 实施决定 |
| --- | --- | --- |
| 一句话生成画布节点、提示词、引用与视频 | `agent-run-executor.ts` 已把 Canvas 计划转换成稳定的 `add_node`、`connect_nodes`、结果更新操作；`/api/agent/runs` 已有任务幂等、恢复与 SSE | 建立受鉴权的外部编排入口，复用现有 Run、项目存储和操作投影；给 zcode 暴露 MCP 工具。Skill 只负责剧本拆分和提示词规则，由用户显式选用 |
| Dola 图片/视频协议 | `services/dola-api` 有 Camoufox 页面签名提交、结果查询、验证会话、首尾帧/参考图上传和任务恢复 | 在 `Dola/provider` 固定一份可独立构建的源代码快照，并用契约测试保持行为一致 |
| 账号与代理 | 当前账号库及导入/导出在 Next.js；通用代理在 `chatgpt-api`，魔法与链式代理在 Mihomo 管理层 | 新项目独立持久化账号、代理绑定和订阅；不以原站运行时作为依赖 |
| 桌面壳 | `apps/desktop` 是 Electron；现有设置与 Dola 管理属于原站页面 | `Dola/desktop` 独立 Electron 应用，主进程持有密钥、文件和网络能力，渲染进程只调用窄 IPC |

## 2. 浏览器内核结论

推荐组合：右侧使用 Electron `WebContentsView` 嵌入 Dola 网页，按账号使用 `persist:dola-<id>` 会话分区；生成仍走当前 Camoufox 签名协议服务。`BrowserView` 已被 Electron 标记为废弃。Camoufox 是 Firefox/Playwright 进程，无法无损塞入 Electron 原生视图。登录受限、验证码或协议状态不明时，打开可见 Camoufox 会话，并显示明确的回到账号页与检查状态操作。不可自动绕过验证码、MFA、额度或服务端限制。

此方案有一个必须实测的兼容风险：Electron Chromium 的站点登录态与 Camoufox Firefox 的指纹不是同一身份。Cookie 仅是会话材料；导入后需要同一账号、同一代理出口，在右侧网页和 `/alice/user/launch` 分别核验。若 Dola 拒绝嵌入 Chromium，右侧改为 Camoufox 画面流与输入转发；这会牺牲滚动/视频流畅度，需在 Mac/Windows 实机量化。不要静默退回无登录网页。

## 3. 产品结构（参考图的结构，不复制其品牌）

- 顶栏：账号/创作/素材/API/代理/设置入口、当前任务状态。
- 左栏：账号搜索、分组、添加/导入/导出、账号在线状态；选择账号切换独立网页会话。
- 中栏：创作抽屉与 Dola 网页。创作抽屉支持图片/视频、模型、比例、时长、数量、普通参考/首帧/尾帧、`@` 素材引用。视频没有“清晰度”选项。内部执行提示词不展示为用户原文。
- 右栏：当前账号和全部账号的任务、图片/视频素材、单项与批量下载、失败原因和重试。
- 设置：浅/深主题、工作空间路径、账号会话数与缓存管理、API 开关和密钥。
- API 页：仅本机监听、密钥生成/撤销、模型列表、创建/查询任务、错误样例和 curl 示例；请求必须显示最终模型和实际参数。
- 代理页：魔法订阅、节点、通用代理组/节点、链式跳板和落地节点、账号绑定、连通性与实际出口。敏感订阅和凭据不得写入普通日志。

配色从桌面现有 `app-theme.ts` 读取方向：浅色 `#f4f8ff` / `#fff` / `#13213f`，深色 `#060913` / `#0b1022` / `#f8fafc`，主色根据桌面设置使用 `#6e53f6`。参考图只提供信息层级，不复制第三方 Logo、文字与素材。

## 4. 数据与执行契约

1. 账号：稳定 `accountId`，显示名、分组、Cookie 密文、登录检查时间、会话分区、代理绑定；导入逐行反馈成功/重复/无效。导出需用户主动操作，支持单个和所选账号。
2. 会话：账号、代理和指纹配置绑定；Cookie 更新提高 `credentialVersion`，旧会话不再用于新任务。登录状态以 Dola 的 `/alice/user/launch` 响应为主。
3. 任务：本地 `taskId`、`accountId`、公开原文、执行提示词、模型/参数、引用素材稳定 ID、上游会话 ID、状态、尝试与文件路径。创建请求使用唯一请求 ID；断线恢复只查已有上游任务，不自动重复创建。
4. 素材：工作空间内按 `assets/uploaded`、`assets/generated`、`tasks` 分类保存；下载先写临时文件再原子替换，校验 MIME/文件尺寸与来源域名，批量下载逐项报告失败。
5. 本地 API：只监听 `127.0.0.1`，Bearer Key 经哈希保存，GET/POST 的模型和任务契约保持稳定。跨进程调用也鉴权；禁止把 Cookie、代理口令或内部提示词返回给 API 客户端。
6. 画布 API：`create_project`、`plan_and_run`、`get_run`、`get_events`、`get_project`、`add_asset_reference`；服务端鉴权和项目归属检查后调现有 Agent Run。MCP 是 zcode 的工具入口，HTTP 是稳定机器接口，Skill 是可选的剧本创作规则。

## 5. 未知项与验证方式

| 未知 | 风险 | 验证/降级 |
| --- | --- | --- |
| Dola 实际可用模型、时长、图片张数 | 参考图和本地预置可能比当前账号的真实权益更宽 | 同一账号网页选择与最小协议重放双重验证；上游拒绝直接显示，不篡改站点配置 |
| Dola 登录与 Chromium 嵌入 | Google/Apple 登录、风控可能拒绝嵌入 | Mac/Windows 真账号手动登录并重启；失败转可见 Camoufox，保留原账号和代理 |
| Cookie 导入/导出格式 | 浏览器格式、JSON、Netscape、纯 Header 各异 | 先支持项目现有纯 Header 和逐行批量；其他格式以明确格式解析器扩展，不猜字段 |
| 代理链 | Mihomo 节点协议与订阅各异 | 使用现有 Mihomo 配置解析/生成方式，实测出口 IP 与 DNS；订阅导入失败不覆盖当前可用配置 |
| 右侧实时观测 | 协议任务未必立即出现在已打开对话 | 用稳定上游会话 ID 导航/刷新到对应页面；不能仅以截图判定任务完成 |
| Windows 包与杀软 | 本机只有 macOS，无法代替 Windows 实机测试 | 可做 Windows 构建和静态检查；登录、代理、目录权限、下载需 Windows 实机回归后才能称完整交付 |
| API 与资源配额 | 自动编排可能重复扣费/提交 | 客户端请求 ID、服务端持久幂等、明确失败后手动重试；不给任意外部请求绕过额度 |

## 6. 实施顺序和验收门禁

1. 固定独立 `Dola/provider` 及契约测试；记录来源快照与许可证，禁用父项目隐式导入。
2. 建立独立 Electron + React 桌面壳：主题、三栏可调整布局、账号视图、`WebContentsView` 多会话、IPC 权限边界。
3. 账号库和手动登录；单/批 Cookie 导入导出、登录态检查、删除/改名/分组、重启恢复。
4. 代理订阅/通用组/链式配置，绑定账号与任务，验证浏览器和协议出口一致。
5. 图片/视频创作，素材上传、`@` 引用、协议任务创建/恢复、网页观察、资源管理、单/批下载。
6. 本地 API 文档与调用；画布外部 API/MCP 集成现有 Agent Run。
7. 相关单测、类型检查、生产构建、真实桌面交互、真实上游对照、Mac/Windows 安装包与重启恢复。每个按钮按浅/深主题和正常/失败/空状态验收。

### 2026-09-27 实施状态

- 已完成独立 Provider 源码快照与测试、桌面三栏壳及账号/Cookie/代理/任务/素材/本机 API 基础流程、画布 HTTP 入口和 MCP 工具。桌面壳采用轻量原生 DOM 与 Electron，未使用 React；已加入代理组 JSON 批量导入和图片缩略图，组轮换策略、可调宽度与精细筛选仍需继续实现。
- 已验证 Provider 74 项测试、桌面 5 项测试与生产模式启动、MCP 测试及握手、主站 TypeScript 类型检查和生产编译。Mac Provider 冻结通过鉴权健康检查，未签名 Mac 客户端 DMG/ZIP 已打包并运行。
- 已在桌面客户端使用真实 Dola 账号手动登录，保存登录态并验证重启后仍可访问。一次 Seedance 2.0 Fast、5 秒视频协议提交被接受并建立真实 Dola 对话；上游最终提示生成失败且未扣额度，客户端已同步并持久化失败原因。一次 Seedream 4.5 生图成功，网页与客户端均得到 4 张，4 张 PNG 已落盘并在素材页显示；成功视频与视频下载尚未验证。
- 仍缺少受权代理订阅和 Windows 实机，代理出站、链式代理和 Windows 安装不能声明已通过。人工验证页若被上游触发，也需真账号走完整流程。

## 7. 交付判定

“无 bug”不是可验证的断言。交付报告必须列出实测平台、账号、代理、模型、任务结果、构建产物及哈希，未测项明确标注。没有真实 Dola 账号或 Windows 设备时，只能报告本地夹具和静态构建通过，不能宣称全部功能真实验收。

## 8. 追加需求（截图 1–6）的问题判定与实施计划

这轮只依据当前仓库的 Web、Provider、Canvas 和 Dola Studio 源码与用户截图分析，没有查询 Dola 网站。既有账号及素材工作空间不能覆盖。

| 需求 | 判定与根因 | 实施与验收 |
| --- | --- | --- |
| 打开工作空间 | 合理，设置只有选择目录 | 主进程调用系统文件管理器打开当前工作空间；空目录与有数据目录均可用 |
| 默认下载目录、自动下载 | 已有完成时落盘到 `assets/generated`，但手动“保存成功”未显示路径，也没有独立 `downloads` 目录与开关 | 工作空间保留原生成素材，默认复制到 `workspace/downloads`；允许另选目录与自动下载开关；显示完整保存位置，重启后持久化 |
| 查询状态打开会话 | 原实现只调用协议状态刷新；用户期望浏览器同步定位到任务会话合理 | 用任务 `accountId` 和已确认的 `conversationId` 切账号并打开 `/chat/{id}`，再刷新任务；缺会话 ID 时明确提示 |
| 15/30 秒、去水印 | 当前 Web 已具备 15/30 秒时长解锁和直接协议提交；独立 Provider 已提取该链路。桌面原先缺少手动取回无水印版本 | Seedance 2.5 提供 15/30 秒，Seedance 2.0 Fast 提供 15 秒；新任务将时长写入 `chat_ability.ability_param.duration` 后按现有协议直接提交。无水印版本沿用 Web 的 `fallback_api → channel=no/codec_type=8/logo_type=unwatermarked → VOD 变体解码`，自动尝试并提供手动重试；真实 15/30 秒结果需账号实测 |
| 魔法订阅报缺少 proxies | 解析器只认顶层 Clash YAML；当前 Web 还支持 Base64 节点列表与 URI | 提取现有 Web URI 解析器，支持 Clash YAML/Base64/URI；订阅 HTTP 发送 Clash UA；无有效节点时给清晰格式错误；真实订阅及出口需独立验证 |
| 通用代理四段格式与测试 | `host:port:user:password` 是现有 Web 常用输入形式；桌面只接受带 scheme 的 URL | 规范化为凭据 URL 并加密持久化；界面不回显口令；通用、魔法各节点和链式出口通过独立 Mihomo 会话访问 Dola 做连通性测试 |
| TXT 批量导入 | 原桌面只支持粘贴；Web `splitDolaCookieFile` 按行处理 | 系统文件选择器读取 UTF-8 TXT，填入批量导入并按行返回成功/重复/无效；分组用已创建分组单选 |
| 创作区 UI 与引用 | 原标题/参数布局、文件名 chip、全历史资产 `@` 选择及弹层被原生浏览器层盖住，均与目标不符 | 控件放同一行；图片缩略图及参考角色同行；粘贴/拖入图片保存至工作空间；`@` 只列本轮已加入图片，删除查询字符、保留素材身份并显示已引用状态；弹层留在创作区原生浏览器边界之外 |
| 浏览器标题/登录按钮 | 手动保存与检查造成额外步骤；原生网页区上方工具栏占空间 | 删除标题和两个操作；返回/刷新按钮直接浮在 Dola 网页内，不占浏览器宽度；登录 cookie 变化时用现有只读登录探针确认后自动保存 |
| 添加账号弹窗/命名/分组 | `required` 让 `method=dialog` 的取消/关闭受校验阻塞，复现截图 6 | 关闭按钮改为显式关闭；名称可空并按 `DOLA1...` 命名；新建分组独立操作、导入和添加使用单选，不隐式创建分组 |

### 验收矩阵与剩余未知

1. 自动化：Cookie 导入/重复、默认账号名、分组、四段代理、Base64/URI 订阅、无水印解析；生产构建和严格 UTF-8 检查。
2. 桌面交互：弹窗取消、参数弹层、粘贴与拖入、`@` 引用、浏览器导航、设置和下载路径、浅深主题截图。
3. 真实账号：在已登录账号上验证任务会话导航与现有四张图片下载到新目录；成功视频、无水印 VOD、15/30 秒上游结果仍取决于真实任务产出及账号权益。
4. 真实代理：用户提供的代理和订阅需要在软件中实际导入后测试出口连通、账号网页与协议同出口；解析通过不等于代理可用。
5. Windows：当前 Mac 开发环境可做源码构建，Windows 安装、浏览器、系统目录和代理 sidecar 仍需 Windows 实机验收。
